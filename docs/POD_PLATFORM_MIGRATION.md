## 2. 备份、预检与数据引入

每次 DDL 前停本项目写入、核对原库/Redis 归属、等待 Worker 心跳过期，做 SQL/素材/配置完整 bundle。
使用当前可信 bundle 在独立副本安装待验迁移并核对；本地库实装在相关实现完成、预检通过后进行。
第 1 步设计阶段没有执行 SQL；第 2—5 步已演练并实装 008—011，012 未执行。

预检报告至少包括：

1. 实例 ID、schema 与 checksum、当前行数和最大 run/batch ID；无秘密连接字符串。
2. 新表名/唯一标识是否冲突、管理菜单是否存在、权限变更精确范围。
3. 排队/运行/取消中/待确认调用/待派发批次数量，调用预占和素材归档状况。
4. 现有 private storage 与 DB 文件记录的大小/SHA核对、孤立项列表；报告不自动删文件。
5. 数据引入计划及差异，只引入 POD 库，原 6379、ERP、门户和其他生产基线不操作。

目录引入只读取旧固定模型的非秘密规格，形成显式、可审核的不可变初始版本。
旧配置的 API Key 不写入 SQL seed、迁移文件或日志；由独立安全凭据录入/引用流程处理，不能顺手复制整个 YAML 入库。
已有创作者不自动开放所有模型或赠送正式点数；需要显式配置资格、模型范围和 grant 流水。
010 的资格、每日提交、存储和用户并发/待执行限制已对 qwen/simulation 生效；模型授权与正式点数不接旧执行、不改原费用或测试单位。首次 backfill 保留原停用/撤权，初始正式点数为零、模型范围为空；新 managed 启用前另做用户授权与点数准备。

## 3. 新执行模式和受控切换

新 `executionMode=managed` 与原 qwen/simulation 分开识别，沿用同一队列、租约、outbox、素材和调用记录。
不把 legacy qwen 任务的 mode 改成 managed，不把原测试额度改成点数，不让未知模式默认成为模拟执行。
managed 需要独立显式开关和服务端付费允许配置；全实例成本上限仍受现有 5 元配置硬限制，
管理设置只能收紧，不能通过添加 provider/model 获得另一份预算或绕过旧已用成本。
显式设置 pod.execution.mode=managed，保留 pod.qwen.allowPaidCalls 和 budgetFen 作为全实例总闸；模型凭据来自目录，managed 不读取旧 qwen.apiKey。API/Worker/创作端同步升级。

切换操作（已实现支持，部署时必须执行）：

1. 禁止新旧模式提交，停止待派发的旧批次/未提交步骤，等待已发调用确认并落盘；不强行清费用或改终态。
2. 对不可立即确认的调用保留原记录、原 Key 来源及兼容核对路径；只能查询/归档，不能再次 Submit。
3. 安装相应迁移，保存真实 cutover 最大 run/batch ID，作为历史识别边界，不能由客户端控制。
4. 配置可用模型及默认值，显式开通用户、模型范围和点数，核对整个实例预算和主密钥来源。
5. 同步启动新 API/Worker/创作端；读服务与状态正常后开放 managed 提交。
6. 所有 managed run 必须有 owner/空间一致的执行快照；缺失即拒绝执行，不以 ID 判断为免费 legacy。

显式 managed 启动通过 gate 保存 managed_enabled/cutover 边界；它不会自动替你停止全部旧批次。运维先完成第 1 步。Worker 对模式不符的任务取消未提交步骤，已提交调用只核对/归档；未知保留预占。旧 YAML Key 不自动导入目录。

已有结果继续按原 owner、运行和素材记录读取。旧 qwen 的失败恢复若会发起新收费调用，切换后返回 409，
引导以旧来源创建新的 managed 报价/任务并明确确认；不在原任务里偷偷换模型、换价或免费重试。
原已成功提交的相同 requestId 仍返回原结果，不能因为切换/报价过期生成第二份任务。
旧 simulation 默认限开发/专用测试账号，不允许外部用户改请求模式绕过正式点数。

## 4. 回退和灾难恢复

DDL 沿用 MySQL 非事务特性；失败保留现场，只接受修复前进或在独立副本恢复完整 bundle。
不删除新账本/列/表来让旧二进制启动，不宣称只回退 EXE 就兼容已带 modelId 的图和新计费任务。
正式回退需重新停写、核对已发生调用、确认新数据与账本保留方案后执行，不能覆盖数据库抹掉供应商已发生费用。
数据库、私有素材、平台素材、密钥 keyId 对应主密钥与原 env 来源必须配套保管，
主密钥不进普通 bundle，单独受限备份；丢主密钥不能从数据库恢复凭据。
恢复工具要追加所有新表计数、平台素材 SHA、执行快照/点数守恒和幂等唯一性检查；副本不接原 Redis/Worker。

## 5. 必须通过的验收矩阵

| 类别 | 必测 |
|---|---|
| 管理权限 | admin/受限运营/两个 creator；直接调用管理接口拒绝；角色撤权/资格停用/到期即时生效 |
| 私人内容 | 管理元信息无正文；root 无 grant 也不能读取；grant 范围、到期、撤销和读取前审计 |
| 秘密 | 凭据/初始密码不进 web 请求缓存、日志、响应、草稿或审计；同请求重试/异内容冲突；缺主密钥拒绝明文回退 |
| 多模型 | 至少两个同类型模型的适配配置/替身回归；文字与生图混用；默认变更、下架、规格变化、凭据轮换不污染旧快照 |
| 点数竞争 | 双击/响应丢失、并发提交/调整、批次全额持有、停止与派发竞争、增量恢复、未知保留、归档重试不扣点、守恒与无负数 |
| 成本 | 新旧调用合计受同实例预算限制；跨 provider 不绕过；超预占用量保留实际成本并告警，不丢回执 |
| 资源 | 每日额度按日/幂等计数；并发上传和生成不能穿透存储上限；任务轮转、队列和 CPU 限制 |
| 模板 | 发布/下架、不可变版本、授权素材、按用户复制、半途失败重试、重复使用不重复复制/建项目 |
| 兼容 | 旧 qwen 读取/未知核对、新模式无快照拒绝、旧请求重试、旧失败迁移新报价、simulation 不能绕正式点数 |
| 升级恢复 | 从 001—007 副本升级、重复 migrate、DDL 中断保护、新机器 init、SQL/两类素材/账本恢复 |
| 页面 | web 与 studio 独立登录，模型选择/重新报价、点数、开通/停用、任务/模板真实页面；桌面/窄屏和键盘操作 |

Go 测试限定本分支单元包和显式 `test/pod` 配置，不运行历史默认 test/。
CRUD 先用生成器产生骨架，再以以上行为验证，而不是只测生成代码能编译。
付费供应商不做无界压测；真实样本需有明确小额授权和可调用账户，本机上限不提额。
当前千问 FreeTierOnly 的外部阻塞单独记；配置可保存、替身通过都不能算真实多模型成功。
Linux、TLS、手机真机及目标容量有环境再验，不用现有 Windows CPU 样本代替。

## 8. 第 3 步目录升级与恢复

008 升级前停 API/Worker、确认归属并创建完整 bundle；使用独立恢复副本先演练 009，再安装本地专用库。
现有 001—008 校验和不改，009 不引入原 qwen Key、不自动创建可执行默认模型、不启用 managed。

```powershell
# 仅在新副本由 008 演练升级到 009，不改变源库
.\scripts\pod.ps1 -Action restore-check -Bundle '.local/backups/bundle-20261113-140036-2365173308' -UpgradeCatalog
# 当前 009 的完整恢复；普通恢复保留 bundle 原版本
.\scripts\pod.ps1 -Action restore-check -Bundle '.local/backups/bundle-20261113-144112-3719393923'
```

UpgradeAdmin/UpgradeCatalog 只用于 restore-check，不能组合；源库升级使用单独 migrate 流程。
restore-check 校验所有历史模型规格摘要、当前与默认指针，并解密所有 encrypted 历史凭据；缺少旧主密钥时失败。
env 类型只核对变量名白名单，不声明外部变量值已恢复，报告 environmentCredentialValuesVerified=false。
主密钥文件不进入 bundle，必须另行受限备份；保留旧 keyId 和 fingerprintKey，不能把 JWT 或数据库当成密钥备份。
恢复副本仍不接 Redis、不启动 Worker。真实供应商 Key、账单和多模型生成另验。
