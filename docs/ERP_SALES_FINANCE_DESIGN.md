# 销售财务基础009：设计与实施

日期2026-10-24，限erp分支、本地ruoyi_go_mt与自有web。用户批准1—5；设计不是验收结果。

1. 仅已发货订单、原总金额明确且币种有效时可显式登记应收；历史订单不自动补账、缺金额不当零。独立冻结原总额及订单行数量，不编造明细单价。
2. 复用008内部账户；同店铺同币种分次收款/最多100应收核销，金额恰好相等、不得超过逐单待收，不支持预收/汇兑。
3. 关联原订单实物退货，人工确认抵减金额与原因（允许明确零额），每退货只登记一次，累计抵减不超过原毛额；不按数量推算退款，不修改库存或原订单。有未核对退货时禁止新收款；后续退货可形成超收待处理，不代表退款。错误收款仅整笔记账冲销。
4. 应收、收款、店铺对账三页；账户入口复用旧页但授权独立配置。财务价格/功能与发货、退货权限分开。列表、详情、写入、重放、导出同时验证店铺及仓库范围；收款头不能因部分可读核销而泄漏全额。平台不代入企业。
5. 独立009六表、租户复合FK/明确支撑索引；默认只读CLI、显式本地确认/新鲜配套恢复证据/共享升级锁。启动只读；既有001—008不改、不自动旧企业加权。补单测、实际接口/并发/故障/撤权、GUI、全量两轮及配套恢复。

锁顺序：员工→店铺→账户(收款动作)→有序原订单→已有收款(冲销)→有序应收；来源/抵减先店铺→原订单，和实物退货在原订单锁串行。不得先拿应收再反锁订单。记录原requestKey/操作者/规范指纹，业务、核销、原结果及无价款最小审计同事务；重放查当前范围后返回原结果。

分页100、输入核销100、稳定主键排序、批量查行无N+1；金额DECIMAL(20,4)字符串。导出限额+1拒绝超限，不截断或展开超大IN。API统一响应、显式camelCase、带context/超时；no-store、HTTP不记查询串/正文，前端未知结果固定原请求且失败隐藏价格，不写持久缓存。

不含真实银行收付/退款、平台结算手续费、销售行定价、成本利润、税/总账、多法人、远程/容量/生产认证。最终证据另见ERP_SALES_FINANCE_ACCEPTANCE。
