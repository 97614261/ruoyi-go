制定日期：2026-11-11。

定位：面向个人创作者、后续可对外提供服务的 POD AI 创意工作流产品。第一版围绕图片与 T 恤预览，采用节点画布，保留后台管理能力。

本文是本分支的当前开发计划，不代表下列能力已经实现。进度只在文末维护；改变范围时同步更新计划并追加决议。

2026-11-13 后续范围已扩展为对外使用：studio 给普通用户，web 给管理员/运营。
新增八步实施计划见 [POD_PLATFORM_DESIGN.md](./POD_PLATFORM_DESIGN.md)；第 1 步设计和第 2 步管理基础已实现，第 2 步本地自动化、恢复与真实登录页面验收已通过，后续多模型与正式点数仍待开发；验收见 [管理基础报告](./POD_ADMIN_FOUNDATION_REPORT_20261113.md)。
本文下列九步继续记录原创作版范围及验收，历史“不开发后台”已由新设计扩大，不代表禁止后续复用 web。

## 1. 目标与第一版边界

### 1.1 用户最终怎样使用

1. 登录后进入项目首页，创建项目，或者从预设工作流创建项目。
2. 在画布填写文字、放入参考图、拖动连线，选择模型和生成参数。
3. 执行一个节点，或者执行整条工作流；直接在节点查看进度、结果和失败原因。
4. 将生成的图案去背景、调整尺寸或放大，放到 T 恤模板上检查位置。
5. 分别导出印刷图案与商品展示图；将流程保存成模板供下次使用。
6. 验证单张流程后，再在同一套模板上处理一批输入素材。

### 1.2 第一版包含

- 登录、个人工作空间、项目管理和持久化画布。
- 文本输入、图片输入、AI 文本、AI 生图、图片处理、商品预览、结果导出七类节点。
- 工作流校验、单节点执行、整条执行、恢复执行、任务记录与结果追溯。
- 个人模板、官方预设模板、私有素材库及鉴权下载。
- 至少一个真实文本服务、一个真实图片生成服务；处理能力逐项接通。
- 一个商品品类（T 恤）的二维印花位置预览。
- 有边界的批量执行、并发限制、额度及用量账本。
- 复用用户已有配套后台；后续需要的模型、预设与额度管理接口按相应步骤设计，不在本阶段另建后台。
- 本地验收、备份恢复、部署说明及适用的回归测试。

### 1.3 暂不包含

- 视频生成、音频、复杂循环与条件分支、任意代码节点、任意 HTTP 节点。
- 多人同时编辑、企业成员邀请、复杂多租户管理、模板市场。
- 在线支付、订阅套餐、公开分享链接、对外开放 API。
- 自建 GPU 集群、强制依赖 ComfyUI、移动 App、桌面客户端。
- 电商上架、订单、生产商下单、物流和 ERP 联动。
- 完整 Photoshop 式编辑器、真实布料变形或 3D 渲染。

以上项目后续单独立项。第一版的二维预览要明确标注为效果示意，不承诺真实印刷成色、纹理或生产商验收结果。

## 3. 界面与节点交互

### 3.1 页面组织

创作端主要入口：项目、模板、素材、任务。账号与用量放在头像菜单，避免展开一大片后台菜单。

- 项目首页：最近项目、新建、从模板创建、运行中的任务。
- 画布顶部：项目名称、保存状态、执行按钮、任务状态、额度。
- 画布左侧：添加节点、模板、素材；用抽屉承载列表。
- 画布中央：浅色网格、节点卡片、连线；缩略图、缩放、框选和适应视图。
- 画布右侧：选中节点的高级参数；基础参数直接放卡片内。
- 画布底部：运行记录和错误明细，默认收起。
- 管理端由用户现有后台承接，本轮不新建页面；后续接口与权限另行接入。

一期不做“输入一句话自动搭整张图”。先提供文本节点与 AI 润色；自然语言生成流程放到图结构和执行引擎稳定之后。

### 3.2 节点定义

| 类型 | 输入 | 配置 | 输出 |
|---|---|---|---|
| 文本输入 | 无 | 文字、节点名称 | `text` |
| 图片输入 | 素材库或上传 | 图片选择、预览 | `image` / `images` |
| AI 文本 | 文本，可选参考图 | 模型、指令、生成参数 | `text` |
| AI 生图 | 文本，可选参考图 | 模型、比例、清晰度、数量 | `images` |
| 图片处理 | 图片 | 裁剪、尺寸、去背景、放大中的具体操作 | `image` / `images` |
| 商品预览 | 印花图片、产品预设 | 印花区域、位置、缩放、底色 | `image` |
| 结果导出 | 图片或结果集合 | 文件名、格式、导出类型 | `files` |

卡片统一呈现：标题、类型、输入端口、主要配置、状态、执行动作、输出预览和输出端口。
操作菜单计划包含复制、重命名、删除；删除连接或节点提供撤销。项目预留 `del_flag`，可恢复删除在步骤 2 实现；模板删除在步骤 7 定义引用保护与恢复规则。

输入端口用明确的类型和必填标记区分。多图输出支持“选定一张”或“整组传入”，不隐式展开为无限任务；每个节点标明是否支持多图，执行前展示预计调用数量。

### 3.3 图结构规则

- 第一期支持有向无环图。禁止自环、循环、重复边、缺失节点和不兼容连接。
- 文本可连接 AI 文本或生图的文本端口；图片只能连支持图片的端口。
- 一个输出可以连多个下游；合流节点必须明确如何处理多个输入。
- 前端立即提示错误；服务端再次完整验证，不能只依赖前端。
- 节点类型和配置有版本号，旧模板不能被新代码静默误读。
- 运行期间仍可编辑草稿，但本次运行使用提交时的快照，后续修改下次生效。
- 修改上游配置会标记下游结果过期，不自动再次生成或扣额度。

## 4. 技术与工程结构

| 部分 | 方案与引入理由 |
|---|---|
| 创作前端 | Vue 3 + TypeScript + Vite，便于复用 Vue 经验并校验图配置类型 |
| 节点画布 | Vue Flow，使用其节点、连线、选择、拖拽、缩放能力 |
| 管理前端 | 用户已有配套后台，本轮不新建 `admin/`；现存 `web/` 保持原样，未集成或验收 |
| 业务后端 | 延续 Go、Gin、GORM，不替换已验证框架 |
| 数据存储 | MySQL：工作空间、项目、快照、任务、素材元数据、额度账本 |
| 队列 | Redis + Asynq：后台任务调度、限流和重试；不拿队列代替工作流状态机 |
| 文件 | 先本地存储接口与鉴权读取，后接 S3 兼容对象存储适配 |
| 模型 | 服务端适配器，统一能力查询、提交、查询状态和结果归档 |
| 进度显示 | 首版用轮询和退避；任务持久化后可按需增加 SSE |

## 5. 数据与接口设计原则

以下为完整产品的逻辑数据集合。步骤 1 仅安装版本记录、工作空间、成员、项目四张 POD 表，
其余随对应业务步骤迁移，禁止把本表当作已经落地的结构。当前契约见 [POD_FOUNDATION.md](./POD_FOUNDATION.md)。

| 数据集合 | 要解决的问题 |
|---|---|
| 工作空间、成员 | 个人空间归属与访问范围；暂不开团队邀请 |
| 项目、画布版本 | 名称、图 JSON、乐观锁版本、节点配置版本 |
| 模板、模板版本 | 公共预设和个人模板，发布版本与实例独立 |
| 素材、素材引用 | 原文件、缩略图、派生关系、引用位置、保留状态 |
| 运行、节点运行、输出 | 一次运行快照、每个节点输入输出、重试和错误 |
| 供应商调用 | 本地请求键、上游任务号、状态、成本、最后查询时间 |
| 批次、批次项 | 一组输入对应的独立任务和每项结果 |
| 额度账户、额度流水 | 预占、结算、释放、调整及审计 |
| 任务投递记录 | 数据提交后可靠投递队列，避免数据库成功但任务丢失 |
| 供应商与模型规格 | 能力、清晰度、数量、参数边界、启停和版本 |

关键约束：

- POD 资源带 `workspace_id`；访问时从登录身份确认空间成员关系，不相信客户端传入的归属。
- 普通用户的项目、模板、素材、任务、下载都受同一空间检查约束。随机 ID 不能代替授权。
- 个人模板引用私有素材时保持原空间限制；公共模板只允许引用已审核的公共预设素材。
- 所有新增业务表包含现有规范要求的审计字段；JSON 名称使用 camelCase。
- 列表有分页和稳定排序；查询索引按“空间 + 状态/时间”等真实查询设计，执行计划验证后固化。
- `workspace_id + request_id`、运行中的节点执行标识和额度事件标识必须有数据库唯一约束，具体范围按业务定义。
- 额度采用整数最小单位，禁止用浮点数直接结算。
- 画布保存带版本号；两个页面同时修改时明确提示冲突，不能静默覆盖。
- 原图或模板被引用时不立即物理删除；按保留政策和引用检查清理，避免历史运行不可追溯。
- API Key 只在后端管理，敏感值不回显，不进入图 JSON、前端包、错误或日志。
- API 路径以 `/pod` 划分；复用 `pkg/response`。新管理接口明确 `pod:资源:动作` 权限，创作端同时校验资源归属。
- 在实现任何新接口前，逐项回答 `CLAUDE.md` 的七个问题，登记到接口设计文档。

## 6. 执行、恢复和计费规则

### 6.1 基本流程

提交请求 → 校验权限、图和模型参数 → 固化运行快照 → 预占额度 → 写任务投递记录 → 后台按依赖执行 → 归档结果 → 结算额度 → 更新前端进度。

图执行状态以数据库为准。Redis 队列负责唤醒任务，不能作为唯一任务记录。需要持久记录已提交的上游任务号，Worker 重启后先继续查询原任务。

### 6.2 状态必须区分

节点至少区分等待、就绪、执行中、成功、失败、取消、上游阻断以及结果待确认；名称在接口设计时统一。

- 单节点执行：使用已有且有效的上游结果；缺少输入时提示，不悄悄重跑所有上游。
- 整条执行：使用固定快照，依赖完成后才执行下游；独立分支在并发额度内运行。
- 恢复执行：同一运行中复用已成功节点的输出，仅重试允许重试的失败步骤并继续未执行节点。
- 新参数、新参考图或主动重新生成创建新的执行记录；不能把它们算作原请求的网络重试。
- 上游失败时，依赖它的步骤标记阻断；其他无依赖分支可按明确规则继续。
- 取消首先停止尚未提交的调用。已提交上游任务不承诺立即停止，也不无条件退款。

### 6.3 防止重复生成与重复扣额度

- 前端双击、客户端超时重试、队列重复投递均须指向同一业务请求。
- 供应商支持幂等键时传同一个稳定键；供应商不支持时，不能仅凭本地去重就宣称上游“只执行一次”。
- 出现“上游可能接受，但本地没收到任务号”的情况，进入待确认状态，查询/对账或人工处理，不盲目再次提交。
- 自动重试限于明确可重试的查询或调用阶段，带上限和退避；余额不足、非法参数不反复重试。
- 额度事件必须幂等；冻结、结算、释放记录成对可追溯。成功但文件转存失败，不能直接把上游费用当作失败释放。
- 预估费用在执行前展示，按已确定规格预占；最终成本和用户额度分别记账，不把供应商成本当作用户售价。
- 最小额度账本在真实付费模型接入前完成；后续管理界面只扩展展示和调整功能。

### 步骤 1：工程、接口与数据边界

1. 清点现有认证、权限、配置、上传、优雅停机和代码生成能力，确认具体复用位置。

### 步骤 3：素材输入、存储与下载

1. 实现图片上传、缩略图、素材列表、选择素材接入节点。

6. 实现租约/心跳、异常退出恢复、上游待确认状态及停机排空策略。
