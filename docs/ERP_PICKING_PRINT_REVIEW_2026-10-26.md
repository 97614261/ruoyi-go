# 拣货打印与未提交扫描的修复（2026-10-26）

本轮发现并修复两个打印问题：打印前重读清单会丢失未提交的扫描；异步准备打印期间页面离开或同包裹被重新读取，旧操作仍可能调用浏览器打印。只修改拣货页面脚本、前端测试和文档，没有改DOM布局、后端、接口或数据库结构。

## 1. 复现与修复

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 扫了一部分再打印，服务器清单没有变 | 扫描数量与输入框被清空 | 每次仍重新读取权限；完整新清单与旧清单序列化结果完全相同才保留内存数量、编码输入和本次数量 |
| 商品条码等清单信息变化 | 打印重读会清空扫描 | 继续清空旧扫描，并提示按最新清单核对；不能只比包裹版本，因为条码修改可能不推进包裹版本 |
| 打印前被撤权限或读取失败 | 不允许打印 | 继续拒绝并清空明细、数量、输入；不因保留扫描而恢复已拒绝的旧数据 |
| 最后一次DOM刷新时离开页面 | 旧操作仍调用 `window.print()` | 在每次异步刷新后核对当前读取代次、页面活跃状态、详情与权限，作废旧打印 |
| 最后一次DOM刷新时，同一个包裹又被读取 | 只比包裹ID，旧操作仍可打印 | 读取代次不同即取消旧打印，即使包裹ID相同 |

只在打印重读时选择保留扫描；切换包裹、正常刷新/读取、提交动作及明确拒绝仍按原规则清理。保留发生在内存，没有新增浏览器存储或服务端扫描草稿。包裹明细读取仍返回服务器最新清单，打印不借旧缓存绕过授权。
