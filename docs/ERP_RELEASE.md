## 3. 本地现有开发库的显式升级顺序

以下为已有本地`ruoyi_go_mt`的操作顺序，不代表每次都执行；步骤2实际结果另见一期结构记录。

1. 核对分支与提交，确认连接的是独立开发库、Redis和上传目录，记录原版本。
2. 停止写流量与任务触发，等待在途任务结束；不要同时启动第二个使用同一环境的Go服务。
3. 备份数据库及附件，在独立新库/独立文件目录核对可恢复性。数据与文件需要同一停写边界；单事务dump不保证与并发文件变更一致。
4. 执行已审查的显式工具，检查每条结果；任一步失败即停，不继续启动服务“试试”。

```powershell
# 仓库根目录；必须已确认目标与备份。不要在原Java/main库执行。
go run ./cmd/tenantconsole -config configs/multitenant.local.yml
go run ./cmd/erpinit -config configs/multitenant.local.yml
# 不带 -grant-demo；注册菜单与为客户开通是不同操作。
```

5. 人工核对新对象、关键约束/索引和预期数据，启动同版本新服务；启动守卫拒绝时查原因，不改代码跳过守卫。
6. 核对健康检查、登录/企业身份、平台不能读客户业务、客户跨企业拒绝、员工仓库范围和菜单开通。

重复执行只允许依照工具已实现的幂等语义；MySQL DDL可能隐式提交，重跑不是事务回滚，不修复任意同名异构对象。
不要调用tenantinit重建已有库，也不要为恢复登录重置现有客户密码。

## 4. 失败时怎么选

| 发生阶段 | 处理 |
|---|---|
| 备份/恢复核对失败 | 不开始升级，保留现状和失败证据 |
| DDL中途失败 | 保持维护状态，记录已生效对象，按实际结构审查补齐或从备份恢复；不声称ROLLBACK已撤销DDL |
| 新代码启动/冒烟失败 | 不放量；仅在已证明旧代码兼容新结构时回退二进制，否则按恢复方案处理 |
| 已恢复写流量后发现问题 | 先停止写入并保存故障现场，再分析增量数据；不能直接覆盖备份丢掉新单据 |
| 附件与数据库不一致 | 暂停发布，按同一快照核对登记、物理文件及摘要；不能只恢复库后宣称完整恢复 |

### 阶段5私有导入存储

`upload.path`之外增加同级`<upload.path>-order-import-private/`，仅后端OS账号访问，不配静态站点/反向代理公开路径，备份包同样按敏感文件保护。源码忽略根目录的该类运行目录；自定义到仓库其他路径时操作者还须确认不被Git追踪。
`sys_file.storage_key=erp-import:<随机文件键>`只登记配额，不能改成/profile链接。数据库与私有文件按同一停写边界备份；旧步骤2附件恢复演练没有覆盖后来新增的私有导入目录，不能作为新目录恢复通过证据。阶段8已单独补验两类文件与登记、任务摘要，但只证明该次本地快照，不保证将来任何备份自动完整。
原文件24小时到期后回收，任务/结果/已创建订单保留；程序每分钟检查、每批最多100个过期任务。删除失败不释放配额；删除后数据库更新失败会在下一轮幂等补偿。重启将PENDING/RUNNING标为INTERRUPTED；超过10分钟仍RUNNING的遗留任务也标中断，用户修复原因后显式重试，原文件过期/丢失则重新上传，不保证自动恢复内存队列。
进程关闭先停止HTTP再取消并等待导入执行器，正常任务/每订单有5分钟/15秒上限；不能同时启动第二个实例共享这些目录和队列。不要为了恢复任务重开已暂停企业或给原员工补权。

恢复必须使用独立副本先验，不覆盖源库/源附件。隔离恢复应用的Redis与任务；旧会话、旧版本权限和恢复后的重新登录策略需按版本明确。
本轮不提供自动执行DROP、TRUNCATE、递归删除、FLUSHDB或批量改密码的捷径。

### 配套恢复的最低验收清单

1. 记录业务停写、后台执行者停止的边界。当前Windows本地演练是在导入全部终态后强制停止已核对进程，不能把它写成已验证优雅排空；生产必须另外验证维护及正常关闭流程。
2. 数据库快照同时保存所有表DDL、行数和逐行摘要；文件清单同时覆盖公开根目录和私有兄弟目录的相对路径、大小、SHA256。禁止跟随软链接、覆盖已有恢复库/目录或把私有文件改放公开根。
3. `sys_file`登记必须按类型验证：`/profile/`关联公开根；`erp-import:`关联同企业的PRESENT导入任务、私有文件大小及SHA256。不能用“不是/profile”跳过私有登记，也不能只验清单内文件而忽略目录增删。
4. 在新库/新目录比对结构、数据、完整文件清单之后，再启动隔离应用；Redis使用新隔离实例/空间、不复制旧登录会话，定时任务和外部副作用先隔离。导入执行器初始化可能把遗留任务标中断，因此精确比对必须在应用初始化之前完成。
5. 实际测试登录/菜单、跨企业和平台拒绝、订单/包裹/库存关联、授权下载两类文件、私有静态路径不可旁路、过期拒绝；仅mysql导入成功不算应用可恢复。副本上的探测写入、漂移及修复不回写源。
6. 核对源库和源文件仍为停写快照后，恢复原服务并检查健康；测试企业只停用保留。备份/恢复副本和原生dump包含敏感数据，不进Git或公开产物；本地留存不等于加密异地备份，需要按运维策略保护和清理，不能拿源码ZIP当备份。Windows创建敏感目录之前须检查NTFS ACL，Go的0700/0600不等同Windows访问控制；本次新备份已另行收紧ACL，不改变源目录权限。

## 5. 正式服务器部署前仍要做

- 准备已演练的生产初始化/升级包；当前本地工具的限制保持不变。
- 使用生产构建而不是Vite开发服务；配置HTTPS、静态资源和同源API/`/profile`代理，明确受信代理。生产API前缀应与`web/.env.production`一致。
- 配置服务进程管理、最小权限数据库账号、私有配置权限、磁盘/备份/日志轮转和告警；敏感配置不放命令行历史。
- 在目标服务器测真实业务混合负载，记录并发、延迟、错误率、CPU、内存、数据库/Redis及磁盘；先定接受阈值，再谈同时在线人数。
- 演练同版本恢复、故障恢复和升级失败处理。历史单租户性能数字不能替代本多租户ERP版本结果。

这些是正式交付门槛，不要求为了基础开发先引入微服务、分布式锁、MQ或通用工作流。
