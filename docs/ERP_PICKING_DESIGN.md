# 拣货与扫码复核设计（2026-10-26）

状态：以下设计已完成本地实现，实际证据见[验收](./ERP_PICKING_ACCEPTANCE.md)，操作见[使用说明](./ERP_PICKING.md)。源码尚未提交，无推送；设计文字本身不代替测试结果。

用户确认版本固化与拣货打包五项。此前245文件与验收清单一致，已本地提交a71b0e6，不推送。
本轮为现有单包裹增加作业入口，不拆单、不新增通用CRUD或库存状态机；沿原表/事务，不需要012或索引变更。

1. 拣货列表分页最多100，单包裹最多100原行，按SKU汇总但不混单位。读取本企业且当前仓库/店铺可见包裹，固定批量查SKU与条码，不含收件人、运单或金额。
2. 默认扫描当前条码，无条码用原SKU编码，保留前导零，大小写精确匹配。包裹内扫描码冲突时阻断，不猜测商品。物理扫码枪按键盘+回车输入；不承诺摄像头识别。
3. 扫描在页面内累计，错货、多扫本地提示；提交最多100编码，服务端按锁定后的包裹/商品重新验证数量完全相等。请求包含version/requestKey，未知结果冻结原请求，仅显式重试。
4. PACK_CHECK事件用既有erp_order_event记录原结果与商品扫描信息指纹（小于500字节），不保存扫描正文。包裹与订单版本推进，库存不变；修改物流推进包裹版本、条码或规格变化改变指纹后，复核失效。清单与扫描码不是永久历史条码档案。
5. 新扫码发货CHECKED_SHIP先检查当前权限/范围和有效复核，再调用原库存ship事务，订单/包裹/实物/预占/流水/事件同事务；原请求重放跨员工/内容拒绝，重试不重复扣库。旧SHIP独立权限与历史行为保留，不把手工发货宣称扫码认证。

菜单9600及erp:picking:list/query/check/ship只登记定义，不给已有企业加权。新建仓库员模板用扫码发货权限替代旧package:ship；已有角色不自动变更。业务管理员仍可按明示权限使用两种入口。
锁序沿员工→店铺→订单→包裹→原库存凭据（发货时）→仓库→SKU升序→商品档案；目录写不反锁订单/包裹，沿SKU锁串行。复核事件写入与最小审计同事务，不原地改历史事件。
打印只输出当前获权清单，打印前重读授权数据；页面离开、切包裹、明确拒绝清理旧结果/晚响应。实体打印出纸另行人工验收。
