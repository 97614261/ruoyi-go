## 运行与原文保护

- 复用 `POST /pod/runs`，新增 `polish` 与 `branch`，请求仍带 projectId、revision、nodeId、requestId、executionMode。
- 服务端在事务内锁定本人项目并比较 revision；从保存图派生本次执行快照，不改写项目。
- `polish` 只接受非空文本输入：派生“原文 → 文本生成”，输出保留目标节点 ID；不执行原图其他节点。
- `branch` 只收集目标及其全部上游，保留节点/连线顺序；共享上游只执行一次。
- 两种操作不接受 baseRunId。润色快照不能充当旧 `node` 模式的普通历史上游，前后端同时排除。
- 保留现有成员校验、幂等键、队列、租约、预算和结果归档。千问操作提交前需要本次付费确认。
- 分支里的上游 AI 节点会重新执行并可能计费。关闭运行弹窗不会取消已经提交的调用。
- 提交前先保存画布；浏览器保留原提交标识，超时只重试原请求。待确认记录损坏时阻止重新提交。
- 润色成功只显示预览。替换前弹窗和父画布都核对原文，期间已修改的文字不会被覆盖；保留原文不改变项目。
- 弹窗打开时屏蔽画布快捷键；保存尚未完成就关闭操作弹窗，不继续创建调用。
- 运行历史标出整条流程、单节点、AI 润色、节点及上游，便于找到对应输出。
