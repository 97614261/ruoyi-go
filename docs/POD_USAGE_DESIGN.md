# 创作者用量设计（后续第 4 项）

2026-11-12。用户选择先做第 4 项；第 3 项有界批量不在本轮。

## 入口与界面

沿用创作端 Manrope、白银画布和钴蓝强调，不增加主菜单。在运行中增加“我的用量”页签。
页面以费用收据为中心，数字使用等宽数字，状态同时显示文字。窄屏纵向排列，不挤出横向滚动。
沿用颜色：纸面 #ffffff、画布 #eef0f4、操作 #3156d3、正文 #242837、次要文字 #626b7b。
文字和明细左对齐，费用分成已确认估算与预占两栏，不增加无关图表或动画。

```text
运行历史 | 我的用量 | 测试额度
本人累计估算费用                 预占金额
模型调用 / 已确认生成图片         失败 / 待确认运行
预算说明：整个实例累计，非个人余额
项目 / 运行 / 状态 / 累计费用 / 图片 / 查看运行
```

保留六位人民币小数，不将测试单位折算成人民币。不提供充值、套餐、支付或新的后台。

## 统计与授权

新增只读 GET /pod/usage?pageNum=1&pageSize=10，统一响应 data 中含 summary、rows、total、budgetScope。
权限 pod:studio:access，并复核本人有效空间和成员；忽略客户端 userId/workspaceId，不提供管理员绕过。
明细上限 100，create_time DESC,run_id DESC 稳定分页。所有统计均为本人当前空间全历史，不以当前页推算总量。
费用从 pod_provider_call 汇总所有尝试；不从可能被恢复覆盖的节点 output 汇总。
图片数仅为已确认调用记录中的 usage.imageCount，包含尚未归档的图片，不代表可下载数量。
submitted 调用保留预占，不当成已知费用；confirmed 的失败调用可为零，绝不推断失败免费。
运行失败/待确认数是当前运行状态数，不是历史每次失败尝试数。
从 pod_run 的 workspace 索引进入，按 run_id 索引连接调用；分页统计批量 GROUP BY，无循环查库。
只选择数值白名单；不返回 receipt_json、供应商 URL、文案、requestId、凭据或他人统计。
多条查询使用只读一致快照事务，服务设置超时；无需改表或安装迁移。
预算仅说明全实例累计上限，不返回全局已用/余额；他人调用不能通过金额差被推算。

## 提交前与异常

画布预览列出此次执行范围、文本调用数、生图数和本地节点数；branch 包含全部祖先，polish 只有一次文本调用，
node 只执行目标且依赖同版本历史输出，workflow 为整个图。预览不代替后端校验，也不承诺最终费用。
恢复只对明确失败开放；未知请求沿用原 requestId，不能生成新键绕过。预算不足先查看本人用量、预占及运行详情，
由部署者核对实例累计上限，不建议反复恢复或删除记录释放预算。归档待确认只恢复下载，不重新生图。

人工核对仅设计：创作者提供本人运行编号给部署者；部署者在供应商账单核对后，未来经独立管理权限、
审计、并发校验和幂等操作结算。当前没有人工改费用、释放未知预占、重新提交未知调用的写接口或按钮。
