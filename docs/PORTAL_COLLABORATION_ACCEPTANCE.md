# 门户个人/团队协作验收（v14）

2026-11-03，portal分支；本地专用ruoyi_go_portal、Redis DB14、127.0.0.1:18085。用户确认执行设计五步，多语言暂缓。本报告记录这轮证据，不承担持续变化的测试数量统计。

## 交付范围

1. 协作设置：文章、产品、单页、外观分别选择直接发布/需审核，默认关闭审核；启用需要另一名有效审核人，不按账号数切换。版本CAS、变更原因、旧/新值事件与四模块影响数量均可查询；策略改变使相关申请失效、取消待发布定时任务，不影响当前线上及待下架任务。
2. 内容及外观审核：保存人稳定userId、不可变快照、单级任一人审核、退回/撤回/历史、通过后单独发布。作者和提交人都不得自审，root通配权限也不例外。普通、批量、定时、站点发布共用事务检查；历史外观开启审核后只能先恢复草稿。所有正式保存（正文、运营设置、恢复副本正式提交、历史恢复）使旧批准失效，个人缓存自身不使批准失效。批准只消费一次，并绑定审核人的持久权限版本；撤权再授权也不能复活旧批准。
3. 询盘跟进：负责人、改派时间线、追加纯文本跟进、下次跟进、今日/逾期待办；原NEW/DONE/SPAM语义保持。隔离默认关闭；开启后普通员工仅看自己的询盘，assign/all管理者可见全部。原列表/详情/处理接口、新跟进、工作台及通知同时执行范围检查。清除联动擦除跟进文字、取消提醒、过期消息。
4. 门户工作台：替换自有后台介绍首页；按当前权限和范围展示本人正式草稿、待审核/通过/退回、询盘待办、有效内容的本人失败任务和真实统计。支持缓存页面返回刷新、草稿及任务跳转。旧无可靠身份的修订不按用户名猜作者。
5. 站内消息：事务outbox去重、托管worker投递/跟进到期、未读/已读和跳转；发布失败、送审结果、新询盘、指派都接入。投递和读取重验当前权限/范围，通知只含通用文案和对象编号，没有客户正文、联系方式、审批意见或任意外链。

## 接口和数据边界

sql/portal/013_collaboration.sql新增9表，v14共45表；没有改原sys结构、旧迁移或自动分配角色。新增权限及表名见设计。新增接口分为/cms/workflow、/cms/review、/cms/inquiry/:id/team|assign|followups、/cms/inquiry/tasks、/cms/workbench及/cms/notifications。所有业务响应走response，错误沿用RuoYi业务码；“数据不存在”业务码为500，不改成HTTP404。
列表用pageNum/pageSize，上限100；固定四项策略/影响和7日趋势属于有界配置/汇总。候选人仅ID/账号/昵称，指派和策略编辑单独鉴权；影响数量为读取时快照，提交事务重验全部当前受影响记录。
投递每轮30条、提醒20条、候选审核通知最多100人；超过100人仍可在授权审核中心处理，首版不向所有后台账号广播。单个事件最多5次投递尝试，数据库本身不可写时保留现场重试；不伪称数据库故障也能持久记重试次数。消息及已结束outbox保留30天，每分钟各批清理最多500行；审核事件及跟进留历史，不自动永久清空。既有私有备份另按保留策略管理。
审批权限版本复用login_user_permission_version:前缀，不新设Redis前缀；Redis不可用时需审核发布失败关闭。CMS私有JSON/素材不得进入公共缓存，HTTP及操作日志不记录询盘原文、跟进/审核意见等参数。
