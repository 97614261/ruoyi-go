# 全局业务弹窗

自有`web/`的默认`<el-dialog>`已统一增加窗口控制。刷新页面后，现有业务弹窗和以后生成的新弹窗自动使用；不用每个页面重新写。

## 怎么用

- 拖住标题栏空白处移动窗口。默认开启鼠标拖拽，移动范围沿用原生视口限制；最大化时暂停拖拽。
- 右上角“—”：最小化到页面底部。当前输入保留，页面可以继续操作。
- 右上角“最大化”：占满浏览器内容区域；再点“还原”回到原尺寸。
- 点底部窗口名称：恢复。原来是最大化的窗口会恢复到最大化状态。
- “×”：真正关闭，沿原有关闭校验执行；底部栏的关闭也一样。

支持多个窗口各自最小化和恢复。控件继承系统size和主题，长正文自己滚动，标题和底部按钮保持可达。最小化不是保存；离开原页面、注销或卸载组件仍按原规则清理，不能当跨页草稿。

## 新页面怎么写

```vue
<el-dialog v-model="open" title="编辑商品" width="760px">
  <!-- 原来的表单 -->
  <template #footer>
    <el-button @click="open = false">取消</el-button>
    <el-button type="primary" @click="save">保存</el-button>
  </template>
</el-dialog>
```

原有`before-close`、`destroy-on-close`、`close-on-press-escape`、默认/头部/底部插槽和`handleClose/resetPosition/dialogContentRef/visible`继续可用。`v-model`在最小化期间仍为true；最小化、恢复不触发业务`close/closed`，也不重发`open/opened`。真正关闭才按原销毁策略处理。

可选项：

| 写法 | 用途 |
| --- | --- |
| `:window-controls="false"` | 此弹窗隐藏最大/最小按钮，保留正常关闭 |
| `:draggable="false"` | 此弹窗禁用标题栏拖拽；与最大/最小按钮开关独立 |
| `:overflow="true"` | 原生特殊选项，允许拖出视口；通常保持默认关闭 |
| `:minimizable="false"` | 仅禁用最小化入口 |
| `:maximizable="false"` | 仅禁用最大化入口 |
| `:window-controls-disabled="saving"` | 保存期间临时禁用最大/最小操作；关闭仍由原规则处理 |
| `window-title="编辑商品"` | 自定义头部没有title时，给底部栏一个名称 |
| `:append-to-body="false"` | 特殊布局保留在原挂载位置；默认挂载body |

`show-close=false`时，最大/最小操作也默认禁用。可监听`minimize/maximize/restore`做展示记录；不要把这些事件当作保存或业务关闭。组件ref新增`minimize()`、`restore()`、`toggleMaximize()`及`windowState`。

关闭拦截兼容原生“取消时不调用done”的写法。若希望异步确认期间禁止重复尝试，请返回该Promise；取消或拒绝后会释放锁。过期确认回调不会关闭恢复后或新打开的窗口。

全局入口位于`plugins/dialog-windows.js`；根`App.vue`挂载恢复栏。默认模板写法自动生效；直接从`element-plus`导入`ElDialog`属于原生入口。`ElMessageBox`确认/提示框与抽屉不在此范围。

## 2026-10-29 拖拽补充

标题栏动作区阻止鼠标按下事件冒泡，点击最大/最小/关闭不会启动拖拽。封装沿用Element Plus原生拖拽，不另造全局鼠标监听。最大化/还原及最小化/恢复保留原生位置处理；真正关闭后新开，在opened时复位，不把上次偏移带给新表单。ref.resetPosition()仍可显式复位。默认入口与上述相同，不要求逐页加draggable；MessageBox和抽屉不因此改变。

本轮自动化验证了默认开启、显式关闭转发、仅新逻辑打开复位，以及窗口切换时表单不重建。真实鼠标位移、窄屏拖拽和各业务页尚未在本轮浏览器补验：浏览器访问被设置关闭，用户选择先完成代码和自动化。前一轮下方最大/最小截图与数据不是本轮拖拽或业务页的验收证据。详见[本轮记录](./ERP_UI_REVIEW_2026-10-29.md)。
