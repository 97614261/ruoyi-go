# 履约页面离开后的操作保护（2026-10-26）

本轮继续检查已有履约入口，发现页面离开后旧确认、逐单循环或迟到回包仍可能生效。已修复订单主页面、单笔审核/取消弹窗、包裹页面和批量履约弹窗；无新增业务模块、接口、菜单、权限规则或SQL。

## 1. 问题与结果

| 场景 | 原问题 | 修复后的行为 |
|---|---|---|
| 审核、取消或发货确认框打开时离页 | 确认完成后仍继续调用旧写接口 | 提交前重新检查所属页面/弹窗，离页、卸载或重新打开后旧确认失效 |
| 批量操作有一条在请求中时离页 | 当前条成功或失败后，还会请求后面的单据 | 只停止尚未发送的后续条；不更新旧结果、不发完成事件触发另一页面刷新 |
| 批量预检中离页 | 成功或失败后还可能继续查下一条 | 两条结果分支都停止，不把旧检查写回新批次 |
| 离开再回到缓存页面并开始新操作 | 旧回包/旧finally可能关新表单、清新文件或提前解除提交锁 | 使用所属生命周期/操作序号隔离；旧操作不再改新状态 |
| 目录运单预检中离页 | 迟到的重复运单结果仍可能弹确认框 | 预检返回先检查所属操作，旧确认和后续保存均不再发起 |
| 订单表单异步校验时离页 | 校验返回后继续创建订单；卸载时甚至可能使用已清空表单 | 校验后、写入前检查所属表单和页面，过期操作终止 |
| 订单页被KeepAlive缓存 | 只处理卸载，收件资料、文件选择和旧详情可能留存 | 失活时清理；重新进入读取当前列表/统计及有效深链接，不恢复旧编辑或导入草稿 |

原单据ID、版本、参数和请求键规则保持。留在同一批次内仍冻结原参数，成功项不重发，未知项只显式用原请求重试。预检的仓库变化与页面生命周期使用不同序号，避免把预检失效误当成取消已经确认的参数快照。

## 2. 离开不代表服务器撤销

此修复阻止前端继续发送尚未发出的操作，并使迟到结果失效；**已经发出的请求可能已经在服务器成功**。没有实现撤销已提交事务，也未把HTTP取消当作业务回滚。

离开后回到列表，应重新核对订单/包裹状态、库存或导入任务，再决定后续操作。批量仍是前端逐单调用，不是持久后台队列；当前弹窗请求键只保存在内存，关闭/离页后不承诺恢复进度。批量提示已写明“离开停止后续单据，当前请求回来核对”。

重新激活的页面可开始新操作；旧操作的成功、失败和finally均不能解锁或清空该新操作。服务端原鉴权、实时范围、版本和领域幂等继续独立约束每次真实请求。
