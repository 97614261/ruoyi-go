# ERP页面离开、超时和重试规则

这是现状使用规则；2026-10-26本轮证据见[跨模块复核](./ERP_ASYNC_REVIEW_2026-10-26.md)。适用于项目自有web，沿用当前后端契约。

## 页面离开时

订单、采购、收货、退货、财务、调拨、商品、物流、库存及基础资料页面离开或被缓存失活时，清理当前草稿、文件选择、私有明细和待确认请求；作废旧读取与操作的归属。

尚未发出的确认、校验后保存、后续单据停止发送。已发出的请求可能已经成功，离开页面不能撤销服务器事务。回来后读取最新列表/明细或导入任务，先核对事实再操作。

返回页面可正常发起新操作；旧请求的成功、失败和finally不应清空新表单、弹出旧确认、恢复旧明细，或提前解除新操作的提交锁。批量仍是前端逐单执行，不是离页后继续运行的后台队列。

## 超时或连接中断后

页面显示结果未确认时，当前请求的目标、版本和内容已固定。即使表单绑定发生变化，重试也不会据此改动原请求。关闭后先查询记录，不能把未知当成失败直接另建一单。

| 接口能力 | 页面如何处理 | 结果如何判断 |
|---|---|---|
| 服务端持久请求键及原结果 | 保留原请求键、版本、内容/文件，显式重试 | 返回原结果或当前明确拒绝；不能重建新键冒充原请求 |
| 版本CAS、唯一编码，没有原结果重放 | 固定原目标/内容/版本，可沿原内容尝试；也可关闭重新读取 | 版本冲突或编码重复不能证明上一请求没成功，必须查询确认 |
| 无请求键的库存状态动作 | 固定本次确认的单据ID/动作，防双击及离页后提交 | 沿后端状态机判断，异常后查询单据及流水，不宣称原结果重放 |
| 图片上传等无原结果重放的文件操作 | 不自动重新上传；离页清本地状态 | 上传可能已登记并计入配额，先核对已有附件；不能承诺重复上传不产生新附件 |

第一类包括采购/收货/双向业务退货、内部财务、调拨、商品与物流档案、订单新建/编辑/审核/取消、订单文件导入和任务重排，以及带请求键的库存单据新建。相同请求重试仍受当前企业、功能权限和资源范围约束。

第二类包括供应商、仓库、旧SKU、店铺、店铺商品及配对、仓库/店铺范围、库存预警，以及没有动作原结果记录的草稿编辑。前端固定内容不等于给这些接口增加了服务端幂等；没有新表、请求字段或隐藏重放缓存。

页面能明确识别的服务端拒绝可以清理旧操作，要求重新查询。旧接口的500也可能用于业务拒绝，前端不能仅凭它推断“确定没提交”；保持保守的未确认处理。具体接口的服务端校验、事务和权限规则仍是最终依据。

## 操作顺序

1. 正常提交期间等待响应，重复点击不会另发请求。
2. 明确成功后再进行下一步；列表读取失败不应伪装成业务写入失败后自动重做。
3. 结果未确认且页面仍打开时，使用页面的原请求/原内容重试入口。
4. 想改变内容、版本或文件时，先关闭并查询现有记录，核实结果后重新打开。
5. 确认框打开期间切走页面，旧确认不应再产生写入；已经发送的当前请求回来后仍须核对。

敏感正文和文件只留当前页面内存，不进localStorage/sessionStorage。本文不承诺关闭浏览器或刷新后恢复未确认进度，也不把取消HTTP解释为业务回滚。
