# 采购退货设计（本地实施范围）

2026-10-23；用户已批准步骤1—5。采购/收货基线本地提交 `ed524c3`。本文是设计，不是测试通过证明；完成状态另写验收报告。

## 1. 业务边界

仅做关联原收货批次的采购退货，不做退款、应付冲销、成本核算、税务、审批、草稿或取消退货。一次提交即过账，历史不可修改/删除。原收货与采购行累计已收不能回写：收10退2表示收10、退2、净8；采购单不重开、不改原状态/version，需补货另建采购。

退货按原批次、原行校验，不得挪用其他批次余量；最多100行，每行1—十亿整数。库存必须有足够可用量（实物－预占），只扣实物，不改预占。供应商/仓库/SKU停用不阻止已收事实纠错，但当前功能、企业和实时仓库范围必须仍有效。原因先去首尾空白，规范化后必填、最多500字且不得含控制字符。无附件、导入导出、金额/联系人字段。

## 2. 数据和幂等

独立 `005_purchase_returns.sql`，仅新增 `erp_purchase_return_order`、`erp_purchase_return_line`；001—004原文不变。头记录精简原结果、操作者、requestKey/hash、原收货、采购、仓库、托管PR、前后退货版本及原因；行冻结原批SKU/单位快照。FK覆盖同企业、同采购/批次/采购行/SKU；应用还验证原收货行ID精确对应。

退货version是原收货批次的退货版本：初始1，每个不可变退货头+1。按原批锁串行、唯一 `(tenant_id,receipt_id,to_version)` 保护。不是采购version。只读详情在一致快照内汇总；头禁止删除，所以count+1稳定。requestKey在原批内唯一，hash包含操作者、目标、原version、规范化行和原因。合法原请求先检查当前身份/仓库再回原结果；同键异内容/异操作者拒绝；当前version变化不妨碍合法重放。

## 3. 单事务与锁序

员工→供应商→采购单→原收货→原IN→仓库→有序SKU/余额。复用采购锁与库存核心，不从库存读取反向锁采购。仓库/SKU在新FK子行之前锁定，避免共享锁升级。

同一事务：实时身份/范围→原请求→版本/批次余量→新PR与退货头/行→库存扣减/不可变流水→原结果与成功审计。任一步失败全部回滚。库存核心只接受repository私有的精确来源证明，限定本事务新PR及原IN，不接收客户端绕过标志。旧库存入口仍拒绝托管IN、新托管PR及其关联纠错；库存只读入口仍按既有范围可用，不附带采购价格。

## 4. 接口和页面

| 接口 | 权限 |
|---|---|
| GET `/erp/purchaseReturnOrder/returnable/list` | `erp:purchaseReturnOrder:list` |
| GET `/erp/purchaseReceipt/:receiptId/returnable` | `erp:purchaseReturnOrder:return` |
| POST `/erp/purchaseReceipt/:receiptId/returns` | `erp:purchaseReturnOrder:return` |
| GET `/erp/purchaseReturnOrder/list` | `erp:purchaseReturnOrder:list` |
| GET `/erp/purchaseReturnOrder/:returnId` | `erp:purchaseReturnOrder:query` |

客户工作空间/no-store/功能权限/实时仓库范围叠加，平台不能代入。页面复用紧凑ERP工作台，分“原收货退货”“退货历史”；原批明细展示收货/已退/可退/本次，确认后立即扣库存。失败保留原请求键、版本、数量，重试不能偷偷换键；成功另刷新原批，历史不提供编辑删除。原收货页入口仅对新return权限显示，不隐含采购query。菜单8000/8001/8002仅登记定义，不给现有企业授权。

## 5. 七项预审与验收

1. 列表分页上限100，详情与提交最多100行。
2. 索引按企业/仓库/收货/采购/主键和FK复用；分页唯一兜底，实际EXPLAIN留证，不承诺耗时。
3. 当前页和批次数量分组批量汇总，不逐行查库；库存有界写循环沿用现有核心。
4. DB继承context与超时，无外部HTTP或新依赖。
5. 权限如表，列表/详情/过账/旧请求重放均复核实时仓库。
6. 统一response/BizError；原因不入通用正文日志，SQL/凭据不回显。成功审计失败整笔回滚。
7. JSON camelCase，无价格/联系人；只新增新域，旧接口不破坏。

验收须包括：分批退/超退/错批、不可用库存、预占不变、两人同版本/同键竞争、异操作者、重放撤权、跨企业、停用主数据、任一写入失败回滚、旧PR旁路、原采购/收货事实不变；新库备份恢复/005不完整与漂移拒启；两轮完整回归；获单独许可后真实员工GUI。未执行项目明确标记，不用单元测试冒充GUI/生产。
