# 仓库基础增强设计（007）

用户2026-10-23批准仓库1—5。仅本地独立ERP库、自有web；不改原库、已应用001—006，不给既有企业加权。本文件是设计，不是通过证明。

## 接口检查单

所有列表pageSize<=100，明细<=100行；仓库/SKU/来源使用已有企业前缀索引，新调拨有双仓状态索引；旧流水的时间/事件为范围内过滤，目前没有独立时间/事件索引，不声称必然索引范围扫描。模糊名称同样不承诺索引扫描。批量关联不逐行查库，context沿用请求超时。功能权限叠加当前企业、实时仓库以及原单店铺权限，平台不能代入。统一response、camelCase，导出限额及并发限制；错误/日志不含正文，地址/负责人不借库存接口外露。

## 1. 仓库资料

独立erp_warehouse_profile保存地址、负责人、version；不ALTER旧表。无扩展行的历史仓库读取version=1，首次编辑在仓库锁下建行并CAS。所有仓库编辑都要求version，同事务更新原主数据、扩展资料及最小成功审计。资料只在仓库query读取，列表/导出不追加私有资料。状态筛选可用，停用不撤销原纠错规则。删除在事务内先删扩展行，旧引用FK仍阻止删除，失败整体回滚。

## 2. 查询、预警、核对

库存余额筛选ALL/IN_STOCK/ZERO/RESERVED_OUT/LOW；ZERO指已有余额行的0，不生成仓库×全部SKU的笛卡尔积。LOW要求明确配置且可用<=阈值，阈值0有效，未配置为null。阈值按仓库+SKU、CAS版本管理；初次version=0，删除配置也需当前版本，ABA由持久版本行避免。列表只提示，不自动采购或推送。

库存到流水到原单遵循目标接口权限；预占来源仅显示当前可读单据，不冒充完整预占总量。流水名称来自不可变单据行/仓库快照，支持时间/事件/单号。单据详情授权不因来源链接放宽。导出遵守相同实时范围与行数限制，不截断冒充完整文件。

核对是只读一致快照，先按有权限余额稳定分页，再按仓库/SKU顺序追加余额缺失的流水组合；比对全部企业流水（不是被店铺阅读范围裁剪后的部分流水）只返回合计/差异，不泄露店铺原单。FK只保护仓库/SKU/凭据关联，不保证余额行存在，因此零净额的孤立流水也报告balanceMissing=true，不当作0库存或一致。不自动改账、不用SUM代替备份。不能从正确性测试宣称容量。

## 3. 调拨

同企业不同仓库，DRAFT→IN_TRANSIT→COMPLETED，草稿可取消/编辑；整单调出、整单收货。调出后无删除/直接取消/反向编辑入口；运输损耗、分批和调拨退回另设计补偿流程。目的仓停用后拒绝收货，恢复仓库后继续，不静默丢失在途。

创建/编辑需两仓范围；调出需源仓范围，收货需目标仓范围；列表/详情任一侧可读，仅披露该调拨明确引用的两仓名称，不授予另一仓库存查询。库存凭据TOUT/TIN由调拨事务私有创建，旧CRUD/退货不能流转；流水只显示当前仓侧，来源跳转仍查调拨权限。

事务锁序：当前员工→调拨头→两仓按ID排序→SKU按ID排序→余额。两仓先于SKU且一次有序锁定，避免反向调拨死锁。调出扣源仓可用，不碰reserved；在途只在调拨单内，不算任一仓可用；收货增加目标实物，不动reserved。新增凭据、明细、余额、不可变流水、调拨状态/版本、动作原结果、最小审计同事务。失败全部回滚。

创建与每动作都有requestKey/规范化hash（含actor/动作/版本/行）。重试返回原结果，旧版本/其他内容/其他人同键拒绝；返回原结果前必须重查当前功能及对应仓库范围。页面保存原请求直到确认结果，错误不偷偷换键或版本。

## 4. 结构与验收

007仅CREATE五表，复合唯一/外键含tenant_id。独立erpwarehouse工具默认只读，apply要求确认本地库及24小时内数据库+两附件根恢复证据，与旧安装器共用advisory lock。启动仅只读核验，完全未安装可选，部分/漂移/孤立记录拒绝启动。

先生成实际新表骨架并保留ZIP，再补领域行为，不运行原始生成菜单SQL。新权限stock:export/alert/reconcile、ledger:export、transfer:*只登记，不给既有企业加权。全部验收只在本轮新建测试企业；完成撤范围、恢复验证码、停用保留。最终报告区分自动化、GUI、恢复与未验收范围。
