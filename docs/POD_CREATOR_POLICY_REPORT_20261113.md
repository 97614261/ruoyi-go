## 已实现与使用位置

| 位置 | 功能 |
|---|---|
| 管理端 → POD 管理 → 创作者管理 | 按账号/昵称、资格筛选，开通创作者 |
| 每行「权益」 | 开通/停用、到期时间、并发、待执行数、每日次数、存储上限 |
| 每行「模型范围」 | 搜索模型，保存允许的模型；明确提交空列表表示撤销全部 |
| 每行「调整点数」 | 人工发放或扣减，填写操作原因；不能扣减预占中的点数 |
| 每行「详情」 | 权益与存储、模型范围、点数与流水三个 Tab |
| 创作端顶部「资格与点数」 | 本人资格、到期日、今日次数、空间、授权模型数、正式点数和流水 |

新账号只分配专用创作者角色，初始正式点数为零、模型范围为空，不接受客户端传入角色列表。
账号为 3—20 位字母开头的 ASCII 字母、数字或 `_ -`，初始密码 8—20 字；密码不写入审计或前端待核对缓存。
管理写操作具有 requestId、版本检查、操作原因及同事务审计；结果不明时核对原操作，不能换编号重复提交。

## 生效规则

- 有效资格允许原创作操作；到期后保留本人读取和下载，拒绝新增/修改；停用拒绝私有内容读写，但保留本人资格和点数说明。
- 资格在 HTTP、资源写事务、批次派发、Worker 领取及新供应商调用意图处复核，不能靠旧页面或旧领取结果继续提交。
- 已提交的供应商调用继续核对、归档和结算，停用不能触发重复调用或丢掉原调用。
- 每日额度采用上海业务日期，按已接受的份数计数；重复 requestId 不重计，取消/失败不返还每日次数，批次派发不二次计数。
- 用户并发和待执行上限受实例上限约束；当前本机分别为 1 和 10。批次等待项与运行占用一并校验，不能把历史报告的 20 项当成当前用户额度。
- 空间包含原图、缩略图、派生结果及回收站；先预留再落盘，文件元数据提交时转为已用，下调限额不删除文件。
- 写盘或提交不明时保留空间预留，不凭租约超时自动释放；精确确认未写文件/已删除后才可释放。
- 点数账户满足 `available + held + spent = granted_total - deducted_total`，只允许从 available 人工扣减。

模型授权当前只保存范围，**尚不能约束旧固定 qwen 模型的选择**。接入第 5 步 managed 执行后才用于正式模型授权和扣点。
