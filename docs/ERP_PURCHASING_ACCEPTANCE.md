## 3. 收货事务与旧入口

- 一次收货1—100行正整数，不超采购余量；采购行、SKU、仓库来自同企业采购记录，不信客户端伪造的SKU/仓库/价款。已确认或部分收货才可继续，收齐自动COMPLETED；关闭余量保留已收事实。
- 一个READ COMMITTED事务完成：当前员工及实时范围校验 → 供应商/采购单锁 → 原请求判断 → 余量/版本校验 → 仓库/有序SKU锁 → 创建收货与托管IN → 调用 `transitionERPDocumentLocked` → 已收/状态/version → 不可变事件及最小审计。任何一步失败全部回滚。
- **先锁仓库/SKU，再插入新FK子行**，避免不同采购单的FK共享锁升级问题；库存核心重用已经持有的锁。不拼接两个公开事务，不反向回锁采购单/供应商。
- 入库只增加实物，不改变销售预占；每批独立收货记录和POSTED IN。供应商停用不阻断历史确认单收货；停用仓库/SKU仍拒绝。
- 指纹包含当前操作者、采购单、动作、输入version及规范化行。当前身份/功能/仓库范围先于重放；旧键相同输入返回原收货/IN/状态/版本，而非最新状态；同键异内容或异操作者拒绝。重复重放不再增库存、事件和审计。
- 采购托管IN不能从手工创建重放、编辑、确认、取消入口独立操作；PR不能引用它或其来源绕过采购。已有库存读取仍允许，不误把写入托管拦截放到读取守卫。独立手工IN/PR保留。
- 表存在性兼容检查只允许固定元数据表名局部System上下文，企业上下文不能逃逸至业务/子查询。未安装004的核心ERP不被误阻断，元数据错误不吞掉。
