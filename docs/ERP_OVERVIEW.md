# 经营概览

适用于 `erp` 分支的客户工作空间。入口为“ERP工作台 → 经营概览”，首页另有获权后可见的入口。
它汇总当前用户可以读取的现有业务，不生成账单、不修改库存、不补历史事实。
设计见[口径设计](./ERP_OVERVIEW_DESIGN.md)，实际验证见[本地验收](./ERP_OVERVIEW_ACCEPTANCE.md)。

## 开通和使用

菜单9400、权限 `erp:overview:list` 只登记定义。平台需要按需给企业开通，再由企业给员工角色授权；本轮没有给已有企业或员工自动加权。
进入概览仍须各区域原有列表权限，以及当前仓库/店铺范围。只给概览权限不会获得订单、库存或金额；平台账号不能代入客户业务。

| 区域 | 同时需要 | 显示与跳转 |
|---|---|---|
| 订单待办 | `erp:order:list` | 当前待审核、待发货订单；点击按同状态进入订单列表 |
| 本地发货 | `erp:shipment:list` | 上海自然日今日、含今天近7日的已发货包裹；点击带对应时间进入发货记录 |
| 库存提醒 | `erp:stock:list` | 有实物、存在预占、低库存的“仓库＋SKU”记录数；点击带库存状态筛选 |
| 采购待办 | `erp:purchase:list` | 已确认/部分收货、仍有毛未收数量且未关闭的采购单；点击勾选“尚待收货” |
| 采购待付 | `erp:payable:list` | 当前可见已登记应付，分币种显示待付/超付；点击单数进入该币种账单 |
| 销售待收 | `erp:receivable:list` | 当前可见已登记应收，分币种显示待收/超收；点击单数进入该币种账单 |

每区可单独刷新，也可“刷新全部”。各区独立读取并显示更新时间，不承诺整个页面来自同一个数据库快照；跳转后业务变化可能让列表数字变化。
页面失活/退出时清空旧结果并作废迟到响应。权限不足、未安装模块、读取失败、合法0分别显示；失败不会被伪装成0。

## 统计口径

- 发货按 `shipped_at` 和 `Asia/Shanghai` 自然日半开区间 `[起日00:00, 明日00:00)`；现有列表时间精度为秒，跳转转换成结束日23:59:59。计数是包裹，不是SKU件数、平台回传或妥投数。
- 库存按记录计数，不能把“件、箱”等不同单位混加。实物 `on_hand>0`，预占 `reserved>0`；低库存沿既有阈值/可用量规则。未安装007时低库存为null，不能伪装成0。
- 采购按订购量与毛收货量判断；退货不重新制造待收任务，关闭单不再待收。仅收货权限不因此获得采购价格和采购概览。
- 待付/待收为逐单 `max(原额－有效抵减－有效核销,0)`；超付/超收为反向正余额，分别求和，禁止跨单抵消。退货未登记抵减时不自动冲账；冲销记账后按当前有效事实重算。
- 金额按三位大写币种分行，保留精确十进制字符串，不跨币种合计。账单单数包含该币种当前可见全部已登记账，不是仅余额大于0的账单。
- 未知订单金额不当作0收入；本页没有销售收入、银行余额、利润或成本指标。

## 接口

六个GET接口统一位于 `/erp/overview/`：`orders`、`shipments`、`stocks`、`purchases`、`payables`、`receivables`。
响应沿 `code/msg/data`；每区 `data.available` 表示模块可用，`checkedAt` 为读取时间。业务数值在typed DTO中，不接受客户端tenantId改变归属。
金额接口支持 `currency`、`pageNum`、`pageSize`，`data.rows/total` 为币种行分页；单页最多100、页面默认10，`total`是币种行数。金额字段为 `dueAmount`、`excessAmount` 字符串，单数字段为 `documents`。
数量接口不靠第一页列表求总数。无模块时数值为空；部分结构、数据库错误、超时必须失败。响应设置 `Cache-Control: no-store`。

概览叠加原功能权限与实时范围：订单沿店铺，库存/采购/采购应付沿仓库，发货/销售应收沿原店铺与仓库规则。跨企业参数和旧会话不能绕过撤权。
每个区域使用独立只读一致读取，固定数量聚合，没有按每个店铺、仓库或结果行循环查询；首版没有缓存、定时汇总或新表/索引。

原列表增加白名单深链接：订单 `status`；库存 `stockState=HAS_STOCK/HAS_RESERVED/LOW`；采购 `awaitingReceipt=true`；发货 `shippedFrom/shippedTo`；应付/应收 `currency`。
这些参数只初始化原筛选，不能扩大服务端权限。对账、单据详情、导出仍检查它们自己的原权限。

## 后续维护

更改统计条件必须同时核对相应原列表与深链接，并补真实HTTP样例。金额、时间窗口、退货/冲销、范围撤回不能只靠静态组件测试。
物流011可整体未装而003包裹已存在，概览应以011新结构识别未安装；启动结构检查继续拒绝部分安装，不放松校验来掩盖漂移。
本地小夹具EXPLAIN只证明查询形状及已有索引使用，不代表大数据容量或生产SLA。
