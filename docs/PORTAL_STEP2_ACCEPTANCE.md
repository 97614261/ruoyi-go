# 门户第2步：栏目与私有素材验收

2026-10-29。本地portal分支；仅操作ruoyi_go_portal，不改原库或ERP。第2步已完成，文章/单页/发布属于第3步。

## 功能与入口

后台“门户管理 → 栏目管理”：文章/产品栏目、上级选择、名称/地址/排序/启停、封面、SEO和备注。
最多2000个栏目、8层；父子类型相同；禁止循环；停父栏目须先停子栏目；有子栏目不可删除。

后台“门户管理 → 素材管理”：PNG/JPEG/WebP上传、授权预览、名称/替代文字/备注修改、引用位置和删除保护。
单张8MB/1200万像素，最多两个并行图像处理；重编码为PNG/JPEG，移除原始元数据，不接受SVG或伪装文件。
私有指不允许匿名访问；有素材查询权限的后台人员使用共享素材库，不是按上传者隔离的个人网盘。
预览通过带Authorization的请求取Blob，在页面内生成临时对象URL，离页/关闭释放；不把登录令牌放在图片URL中。
栏目和素材修改/删除均提交当前version，过期写入拒绝，不静默覆盖。

## 数据与权限

- 显式v1→v2迁移新增cms_channel、cms_asset、cms_asset_ref；当前24表、两条结构版本记录。
- 只插入6000—6014范围内11条新菜单定义；没有改sys表结构或给旧普通角色分配权限。新门户管理员沿原admin语义拥有管理能力。
- 迁移入口cmd/portalmigrate默认只预览；显式执行前备份并停止门户，验证旧结构后才能升级。启动继续只读校验最新已安装版本。
- 从现有生成器为channel/asset产出完整CRUD底稿，再扩展CAS、层级/引用和私有上传；原底稿ZIP和Go忽略的归档目录留在logs/portal-step2。
- cms_asset_ref由栏目事务维护，不提供任意引用增删接口；引用和删除共享数据库行锁，不能绕过前端禁用按钮删除被引用文件。
- 素材文件位于独立uploadPath-portal-private，不在匿名profile根目录；返回JSON不包含storageKey或磁盘路径。
- 删除先在事务中检查引用并停用素材，再尝试移除物理文件；文件被占用时可能留受保护残留并记警告，不声称已经释放磁盘空间。

## 发现并修复的共享缺陷

撤权首轮失败为NOSCRIPT：pipeline中Script.Run排队时没有实际错误，Exec后才失败，无法触发Run的EVAL回退。
权限版本推进改为在pipeline明确发送EVAL，保留原Lua、200人批次、键前缀和永久版本语义；不清空Redis或全局脚本。
新增无网络冷脚本缓存回归，真实旧token撤权复验通过。失败用例遗留账号的专项检查已执行，未发现仍匹配的活动测试账号。
该修复仅在portal工作区，未自动提交/合并main或ERP。
