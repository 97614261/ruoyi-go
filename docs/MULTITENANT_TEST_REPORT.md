## 发现并修复

1. 原有 OR 条件直接追加 AND tenant_id 会发生运算优先级逃逸，WHERE 和 JOIN ON 均改为整体分组。
2. 用户停用/改密在目标归属未确认前撤销全局用户会话，可能误踢其他企业；现在先做租户内存在性检查。
3. userType、tenantId 不能由新增用户请求决定；身份强制为普通员工，归属由服务器赋值。
4. 旧固定管理员 ID、公开附件 StaticFS、任务日志 TRUNCATE 不适用于多租户，均已替换。
5. 调度快照与异步操作日志必须保留租户上下文；任务更新不得把快照归属丢成0，停用/到期企业不执行任务。
6. 生成器的 Count/Scan 和 map Updates 没有模型 Schema，改用显式 TenantTable，不能只依赖实体字段识别。
7. 新企业只复制白名单公开初始化项，避免将平台自定义凭据或内部字典复制给客户。
