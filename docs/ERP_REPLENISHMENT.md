# 采购补货建议怎么用

位置：**采购管理 → 采购单 → 补货建议**。这是V1.1第一项内部业务增强，不依赖平台商户账号。

## 操作顺序

1. 在现有库存页面配置仓库＋SKU的最低可用库存。未配置的商品不会自动出现；只显示启用仓库、启用SKU。预警配置可以早于余额行创建，不要求先造一笔假入库。
2. 打开补货建议，选到货仓库，点“查询”。缺口为0表示现有库存或采购计划已覆盖；表格也保留这些行便于核对。
3. 勾选需要补货的商品。同一张草稿只选当前仓库、当前页的1—100项；重新查询/翻页会清空选择。
4. 选一个供应商，核对币种、数量，手填单价，允许0；不自动读取历史采购价格。
5. 点“生成采购草稿”。返回采购列表后，继续“确认采购”→“采购收货作业”→实际到货入库。

## 数字怎么算

- 可用 = 实物 − 已预占。
- 补货目标 = 预警线＋1；因为原预警在可用量小于或等于预警线时触发。
- 草稿待采购 = 当前仓库对应SKU的DRAFT采购量。
- 在途未收 = CONFIRMED/PARTIAL_RECEIVED的采购量减毛收货量；CANCELLED/CLOSED/COMPLETED不计。
- 缺口 = max(0，补货目标 − 可用 − 草稿待采购 − 在途未收)。

例如预警线5、可用0、没有其他采购，建议6。生成6件草稿后缺口0；确认后变成在途6；收到2件后可用2＋在途4仍覆盖目标。此时关闭剩余4件，在途归0，缺口回到4。

这是最低补到线上的建议，不是按销量预测或采购周期计算。实际采购数量由用户确认，每行沿原采购限制1—十亿；大缺口的默认建议先封顶十亿。建议校验支持非负、实物不少于预占的库存，库存和预警各在当前一万亿范围内，超界须先核对。采购退货保留原毛收货，不把历史退货当“供应商还会补发”。调拨在途不计入本阶段采购建议。

## 权限与失败处理

查看接口需erp:stock:list＋erp:purchase:list及当前仓库范围；生成另需erp:purchase:add。页面仓库/供应商选择器分别使用原warehouse:list、supplier:list。预警修改仍需原stock:alert；不能因能补货就改预警。原采购query价格权限不被列表或补货权限隐含。

生成时服务端会在仓库锁内重读预警、库存和计划。建议依据变化会拒绝，不自动替你改量下单。同一旧建议跨供应商并发，只允许一个先生成，其他请求须重新核对。

结果不确定时表单锁住原内容/请求键，只能原请求重试；关闭后先查采购列表，不换键盲目再建。权限撤回后原请求重放也拒绝。最小化/恢复保留内容，离页清理；本页面不保存跨页草稿缓存。
