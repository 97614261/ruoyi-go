### 后台操作

位置：**POD 管理 → 模型管理**。

- “供应商与凭据”：新增厂商或独立中转渠道、加密保存/轮换凭据、启停。
- “模型目录”：选择型号预设，维护能力、成本、用户点数及超时的不可变新版本，启停/展示模型。
- “默认模型”：分别设置文字和图片默认值；这一步不替用户授予模型权限。
- “创作者管理”：显式配置用户的模型范围及正式点数。

模型表单根据厂商选择正确的文字/图片类型；预设展示来源、核实日期和限制说明。
自定义渠道可选文字协议、图片质量、按比例指定尺寸及图片结果格式，保存后纳入历史版本摘要。
成本填写人民币，使用整数 micros 精确换算。空白不是免费，免费必须明确填 0。
新型号预设的点数按每元 100 点初始化，管理员可发布新版本调整，不改变历史消费价格。

列表的“真实响应通过”以当前模型版本与当前凭据版本的成功回执为依据，凭据轮换后不能沿用旧证明。
“配置就绪”只说明本地配置齐全，不证明供应商可用；替身集成测试只写入恢复副本。

### 本机 Base64 图片回执容量

本机 MySQL `max_allowed_packet` 为 4 MiB。单张 Base64 可达 8 MiB 原图，整个响应上限 48 MiB，
如果调用后才发现数据库不能保存，会丢失可恢复回执，因此在创建付费调用意图前检查服务端/客户端容量。

- 支持 URL 结果的渠道可在模型新版本选择“图片结果 → URL 链接”，沿用当前数据库配置。
- Base64/自动识别渠道要求服务端与客户端单包至少 64 MiB；改变服务端配置后重启 API/Worker，建立新连接。
- 容量不够：返回 `receiptCapacity`，无供应商请求、无成本调用记录，运行失败后释放未提交点数。
- URL-only 渠道若返回 Base64，按无法确认的异常响应保留预占，不重发；需要核对渠道是否遵守其协议。
- 本轮没有运行 SET GLOBAL、改共享 MySQL 配置、改现有表或追加迁移。

`pod.ps1 -Action doctor` 新增该项只读提示。仅调整单个连接或只改客户端 DSN 不够，不能绕过服务端限制。

## 4. 可靠性与安全边界

当时供应商地域和 Base URL 固定。后续支持在「编辑供应商」修正自定义渠道同域名下的路径，自动生成新模型版本并保留旧版本；不同域名或计费主体仍须独立建供应商，不能借轮换 Key 更换计费主体。
自定义渠道仅接受不带端口、密钥、查询参数的公网 HTTPS 域名，支持 `/v1` 等路径前缀。
禁止内网、回环、云元数据地址；DNS 每次解析后校验全部结果并固定连接 IP，禁用系统代理/跳转。
图片 CDN 请求不携带供应商 Authorization，不将 URL、Base64 回执或存储键放入公开 DTO。
两种执行模式的回执写事务关闭 SQL 正文日志，避免慢查询/失败日志展开私人文字、签名 URL 或完整 Base64 图片。

继续使用原调用意图、回执、预算、点数和私有归档链：先持久化意图再调用，先持久化确认回执再归档。
下载/归档失败只处理原结果，重复执行不再次 Submit、不重复结算。超时/网络不明/异步响应均保留预占，不自动重试。
新字段采用 omitempty，旧模型版本摘要不变。未重写 001—012，没有新的 HTTP 路由或数据库迁移。
