# 2026-09-02 稳定性、Redis A/B 与依赖恢复报告

## 1. 结论

- 当前单服务器、单 Go 进程没有新增 P1/P2 代码问题。
- 10 小时稳定性测试通过：28,156,531 次读请求错误 0；241 轮参数 CRUD 和 31 次 XLSX
  导出错误 0；Go RSS 从约 97.03MiB 到 99.30MiB，峰值 101.66MiB。
- 外部 Redis 连接池 A/B 选择 `poolSize=32`。40 只减少池等待，没有继续改善吞吐和延迟。
- Redis/MySQL 重启恢复通过：故障期间健康检查返回 503，依赖恢复后业务接口重新返回 200。
- 没有修改数据库结构、约束、索引或 Redis Key 前缀；测试会话和登录记录已清理。

## 2. 10 小时稳定性

目标为 Alibaba Cloud Linux 3、2 vCPU、约 1871MiB RAM。压测分为 2 小时只读门禁和 8 小时
混合稳定性阶段，全部使用 30 分钟分段，避免压测器长期保存延迟样本导致自身内存增长。

| 阶段 | 并发 | 请求数 | QPS | P95 | P99 | 错误 |
|---|---:|---:|---:|---:|---:|---:|
| 门禁前两段 | 50 | 2,874,892 | 798.58 | 96.38-96.55ms | 118.17-118.46ms | 0 |
| 门禁后两段 | 80 | 2,838,341 | 788.43 | 154.76-154.77ms | 185.32-185.44ms | 0 |
| 混合稳定性 | 80 | 22,443,298 | 779.28 | 155.32-158.00ms | 186.58-189.24ms | 0 |

全程 Redis 超时为 0，结束后 `pendingRequests=0`。测试期间最大 pending 为 61，说明 20 个
连接在 c80 下是明确排队点，因此继续做了独立压测端 A/B，而不是直接猜一个更大的值。

## 3. Redis 连接池外部 A/B

压测器运行在独立 Windows 主机，通过公网直连 Go 的 18081 端口；目标机只运行被测服务和
MySQL/Redis。20/32/40 采用交错顺序各跑 3 轮，每轮重启 Go、预热 5 秒，再执行 `c80 × 60s`。

| poolSize | QPS 三轮 | QPS 中位数 | P95 中位数 | P99 中位数 | 等待次数中位数 | 错误/超时 |
|---:|---|---:|---:|---:|---:|---:|
| 20 | 788.47 / 836.10 / 841.40 | 836.10 | 136.30ms | 175.60ms | 135917 | 0/0 |
| **32** | 817.51 / 865.41 / 867.55 | **865.41** | **135.96ms** | **174.55ms** | **60565** | **0/0** |
| 40 | 849.03 / 857.40 / 858.31 | 857.40 | 138.88ms | 178.98ms | 14981 | 0/0 |

公网波动使单轮 QPS 有噪声，因此使用交错顺序和中位数。32 相对 20 吞吐提升约 3.5%，等待
减少约 55%，P95 基本不变；40 没有继续改善可观察性能。最终选择 32，并补跑 10 分钟确认：
505,431 次请求、842.38 QPS、P95 140.67ms、P99 183.04ms、错误 0。

## 4. 依赖恢复

| 故障 | 故障期健康检查 | 启动后恢复时间 | 恢复后用户列表 |
|---|---:|---:|---:|
| Redis 停止 | HTTP 503 / redis down | 42ms | 业务码 200 |
| MySQL 停止 | HTTP 503 / mysql down | 1323ms | 业务码 200 |

这是单实例故障恢复验证，不是高可用验证。依赖停止期间服务会不可用；生产操作仍需维护窗口、
摘流量和可用备份。

## 5. 大数据边界

- 10 万行 Excel 内存测试已复跑：数据切片约 14.5MiB，导出堆峰值约 89.6MiB，现有
  `MaxExportRows=100000`、`MaxConcurrentExports=2` 保持不变。
- 当前目标库 `sys_oper_log` 只有 892 行，三轮 COUNT、首屏、10 万 OFFSET 和最深页 SQL
  均约 22-32ms，这个结果不能代表 500 万行。
- 按“不改现有数据库”的边界，没有向目标库灌入 500 万条日志。该场景只能在隔离数据库副本
  执行；在拿到证据前不新增索引、不修改冻结 SQL，也不把 892 行结果外推为大表结论。
