# 本地ERP版本整理清单

当前可用模块见[蓝图](./ERP_BLUEPRINT.md)，新企业操作见[指南](./ERP_GETTING_STARTED.md)，本轮证据见[验收](./ERP_ENABLEMENT_ACCEPTANCE.md)。
本轮未执行git add/commit/push。工作区包含此前多轮未提交模块，不能只提交新启用页面而遗漏其依赖。

## 提交分组建议

| 分组 | 内容 | 注意 |
|---|---|---|
| 库存/退货扩展 | 006/007、状态机/托管保护、测试和页面 | 连同已有SKU/仓库/订单接口修改一起检查 |
| 采购/销售财务 | 008/009、精确金额/核销/冲销、相关UI及测试 | 内部记账边界与权限一同提交 |
| 商品与物流 | 010/011、生成器扩展后的聚合、包裹快照/发货记录 | 不能遗漏启动校验、嵌入SQL、路由注册和菜单 |
| 联动/概览 | 下载删除边界、完整业务链/丢回包测试、概览及筛选 | 原响应和历史手工入口继续保留 |
| 企业启用 | 9500、两个只读GET、模板预填/窄屏修正、用法/验收 | 不自动修改既有企业权限，不产生012迁移 |

以上是逻辑分组，不保证任意拆分后都能独立编译；提交前需要核对依赖和实际diff。保留用户已有改动，不能为凑提交组自动回滚或重写工作区。
本轮仅负责已标记文件的复核与验证，工作区其他历史改动不因为出现在清单里而被宣称逐行重审通过。

## 应纳入版本

Go源码、测试、公开版本化SQL、项目自有web源码与锁文件、开发/安装/验收文档、验证脚本。
必须将启动注册、结构守卫、契约权限清单、对应菜单定义与实际功能同时纳入，不能只提交某个页面或单个DDL。
新增普通CRUD继续先用生成器；本轮只有固定只读检查和已有角色表单的预填，没有伪造新CRUD/业务表。

## 不纳入版本

私有配置/账号、JWT或数据库密码、日志与备份、MySQL/Redis数据目录、公开/私有附件、运行exe、node_modules、dist、test/results。
`logs/erp-enablement-20261025/`（包括fresh-root）整体为私有本地证据，不能force add。

## 固化前核对

1. 确认erp分支和HEAD、当前dirty清单；核对本轮交付回执的文件哈希，避免把同名旧二进制当最新源码。
2. 根据实际提交组合运行 `scripts/verify-erp.ps1 -Integration -Count 2`，并记录结果目录。需要真实界面和恢复的变化另附对应证据。
3. 核对菜单仅定义、已有授权未变化、测试企业停用/范围清零/验证码恢复，确认临时隔离进程已停止。
4. 列出源/目标schema、001—011顺序、私有配置项、前后端构建和校验和、配套恢复点。没有012，不能仅因为有新菜单便运行DDL。
5. 在提交前再次检查git diff和秘密文件忽略规则；提交后以新的commit号更新发布记录，推送另按用户指令执行。

本轮最终 `logs/erp-enablement-20261025/delivery.json` 记录受审核文件哈希/运行产物与测试恢复引用；`working-tree-manifest.json` 是排除运行/私有目录后的当前变更清单，不是已提交或全历史审查证明。
正式发布前还需另做目标服务器、生产初始化/升级和回退演练。当前本地CLI限制保持，不靠删除DSN检查取得“支持生产”的假象。
