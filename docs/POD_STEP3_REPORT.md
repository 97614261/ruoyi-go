## 1. 现在怎么用

1. 打开 `http://127.0.0.1:5177/`，用本地 `.local/accounts.json` 中的 `pod_creator` 登录。
2. 顶部进入“素材”，点击“上传图片”，选择 PNG、JPEG 或 WebP。上传后显示图片尺寸、大小和项目引用数。
3. 点击素材可查看原图，再点“下载原图”；原始文件字节与透明通道保持不变。
4. 进入项目，添加“图片输入”节点，点“选择或上传图片”。在弹窗中选择，最多 8 张，点“加入节点”。
5. 等待顶部“已保存”，刷新后素材选择仍在。右侧参数面板可以逐张移除；这不会删除原素材。
6. 在“素材”页将未被项目引用的图片移入回收站，切到“回收站”可以恢复。

图片顺序按选择顺序保存。选择弹窗可跨页选择，也可直接上传。
缩略图最长边 480px，透明背景用棋盘格展示；不会把缩略图冒充原图或 AI 生成结果。
JPEG 的 EXIF 方向、ICC 色彩管理与印刷校色不属于本轮处理能力；下载保留原文件。

## 2. 接口与响应

开发代理仍在请求前加 `/api`，后端实际路径如下。全部经过登录、请求体限制和 `pod:studio:access`，
业务层另校验本人有效个人空间与成员。管理员不绕过私有资源范围。

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| `GET /pod/assets` | `pageNum/pageSize/deleted=true或false` | 顶层 `rows/total` |
| `POST /pod/assets` | multipart，唯一文件字段 `file`，仅一张，不接受附加字段或 URL | `data` 素材元数据 |
| `GET /pod/assets/:id` | 规范正整数十进制路径 ID | `data` 素材元数据 |
| `GET /pod/assets/:id/content` | `variant=thumbnail`（默认）或 `original` | 鉴权图片二进制 |
| `GET /pod/assets/:id/download` | 路径 ID，只下载原图 | 附件二进制 |
| `DELETE /pod/assets/:id` | JSON `{"revision":"1"}` | `data` 删除后元数据 |
| `POST /pod/assets/:id/restore` | JSON `{"revision":"2"}` | `data` 恢复后元数据 |

元数据字段：`assetId/workspaceId/parentAssetId/source/originalName/mediaType/byteSize/width/height/revision/deleted/referenceCount/createTime`。
ID/revision 为字符串；`parentAssetId="0"` 表示上传原图没有上游素材；`source` 当前为 `upload`。
`referenceCount` 是引用记录数，同一项目的两个节点引用同图算两处，包含回收站项目。
响应不含 storageKey、磁盘路径或文件哈希；时间沿用 `2006-01-02 15:04:05`。

列表默认每页 10 条，上限 100，超出截断；图库每页 24 张。
固定 `create_time DESC, asset_id DESC`，没有名称模糊搜索或客户端自由排序。
删除/恢复使用版本比较并递增 revision，旧版本返回 409；暂不提供永久删除。

业务错误沿用 HTTP 200 + `code/msg`，参数 400、未登录 401、空间拒绝 403、不可见素材 404、
被引用/版本冲突 409、图片处理并发已满 429。一般内部错误隐藏实现细节。
二进制成功使用实际 `image/png`、`image/jpeg` 或 `image/webp`，下载包含安全编码的附件文件名，
并设置 `Cache-Control: private, no-store` 与 `X-Content-Type-Options: nosniff`。

前端使用 Authorization 请求二进制，再以本机 Blob URL 展示；不把 Token 放在 URL 中，
也不把 Blob URL 写入图 JSON。切换图片/账号或卸载组件时撤销展示 URL。

## 3. 图片与存储边界

| 限制 | 默认 | 配置/固定边界 |
|---|---|---|
| 单文件字节数 | 10 MiB | `pod.maxUploadBytes`，0/未填使用默认，最高 20 MiB |
| 解码像素数 | 2400 万 | `pod.maxImagePixels`，0/未填使用默认，最高 4000 万 |
| 单边尺寸 | 12000px | 固定 |
| 节点选择数量 | 8 张 | 固定，同一节点不允许重复 ID |
| 同进程图片处理并发 | 2 | 超出返回业务码 429，不无限排队 |

负数/超过配置上限拒绝启动；有效限制随 bootstrap 的 `assetLimits` 返回。
上传为流式 multipart，不借用公开 `/common/upload`，不生成公开 `/profile` URL。
请求体另加文件上限 + 64 KiB 的 multipart 总边界；图片内容最多读上限 + 1 字节。
先读图片头限制尺寸/像素，再完整解码验证和生成缩略图；实际格式必须匹配扩展名，声明 MIME 也须匹配或为 octet-stream。
SVG、GIF、伪装类型、截断文件、路径/控制字符文件名均不接受。

存储接口在 `pkg/storage`，当前实现为私有本地目录，读取返回流与长度，不把业务授权放进存储层。
原图和缩略图分别用随机文件键写入，独占创建、同步并关闭后才登记元数据；前端传来的文件名仅作展示。
文件键严格匹配随机十六进制名和受支持后缀，文件操作通过 Go `os.Root` 限定根目录，并要求普通文件。
读取先检查素材归属和删除状态，再取数据库内的文件键，不接受用户提交磁盘路径。

本轮没有外部 URL 导入、服务端结果抓取或短时公开链接，不发起任何素材来源 HTTP 请求。
未来真实模型结果归档必须另外实现协议、IP、重定向、大小与时间限制；本轮拒绝 URL 输入不能算那部分 SSRF 验收。

## 4. 引用、删除与清理策略

`imageInput.config.assetIds` 现在接受最多 8 个不同的规范 ID 字符串。
纯图校验检查结构，项目写事务再一次批量核对素材存在、有效且属于同一工作空间。
图保存与引用记录替换放在同一事务；失败回滚，不会留下半张图或丢失旧引用。

项目保存与素材删除按相同顺序锁定空间/成员，再锁资源，避免“图保存成功却引用了已删除素材”。
有任意项目引用就拒绝删除，软删除项目继续保留引用，恢复后仍能打开原素材。
需要解除引用时先恢复项目，移除图片或图片节点并成功保存，再删除素材。

当前保留策略：

- 正常素材删除只改状态，不删原图或缩略图；恢复增加版本并重新开放访问。
- 不自动清空素材/项目回收站，不按文件年龄删除图片，尚无物理清理接口或定时清理任务。
- 缩略图写入失败且尚未尝试数据库登记时，回收本次明确创建的原图；不清理其他文件。
- 数据库提交报错可能存在结果不明，保留文件供核查，不直接删除可能已登记成功的素材。
- 异常退出或登记失败可能留下孤立文件，后续物理清理需核对数据库、引用和备份，不能手工按“旧文件”批量删除。

这会保留磁盘占用，后续开放给其他用户前仍需容量、配额与孤立文件巡检；不把当前软删除称为释放磁盘空间。

## 5. 数据迁移与生成器

`002_assets.sql` 新增三个 POD 表：

| 表 | 内容与索引 |
|---|---|
| `pod_asset` | 归属、原名、类型、尺寸、版本、软删除、上游素材 ID；空间/状态/创建时间/ID 联合索引 |
| `pod_asset_file` | original/thumbnail 两种文件、随机键、类型、大小、尺寸、SHA256；素材+variant 主键、文件键唯一 |
| `pod_project_asset_ref` | 空间、项目、节点、素材引用；项目+节点+素材主键，素材引用索引 |

原图与其派生缩略图通过同一 assetId + 不同 variant 对应；`parent_asset_id` 为未来处理生成的素材保留溯源位置，本轮不伪造处理结果。
三表都有审计字段。没有数据库外键，归属与引用完整性由事务验证。

`003_asset_node_identity.sql` 将新引用表的 node_id 改为 `ascii_bin`，与图 ID 的 ASCII、大小写敏感规则一致。
这是补充检查发现的边界差异；没有回写已安装的 001/002 或篡改旧 checksum。

本地迁移前已生成 SQL 备份。`podsetup -mode migrate` 仅接受回环 MySQL、匹配的 POD 配置、001 与 Redis 实例标记，
在同一连接获取迁移锁，核对已有 checksum/state，只执行内嵌 002/003。
重复检查已 ready 版本不重复建表；DDL 失败保留 installing，拒绝盲目重跑。
服务启动要求 001—003 均 ready 且 checksum/实例匹配；check 不执行迁移，init 仍拒绝已有库。
新建库的 init 会接着安装 002/003，本轮真实验收针对现有独立本地 001 升级，未另跑一次从零建库。

按仓库规范，先用现有生成器生成素材 CRUD 的 9 个文件，再适配私有资源 model/repository/service/handler。
证据在忽略提交的 `.local/generated/asset/`；临时生成测试已移除，未安装通用导出、管理页、自动路由或菜单 SQL。
图片解码与缩放复用已有的 `golang.org/x/image` 版本，未增加供应商 SDK 或前端依赖。
