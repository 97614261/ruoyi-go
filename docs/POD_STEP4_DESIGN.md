# 第四阶段实施设计

本阶段使用测试执行器，不调用付费模型。实施顺序：执行计划与状态机 → 数据迁移和事务账本 → Asynq/独立 Worker → 运行界面 → 故障与权限回归 → 报告。

## 接口前七项核对

| 核对 | 方案 |
|---|---|
| 分页 | 运行、额度流水默认 10，最大 100；运行详情节点受图上限 100 约束 |
| 索引 | 空间+创建时间+ID、空间+请求键唯一、运行+节点唯一、状态+租约、投递时间、账户+事件键唯一 |
| N+1 | 列表不查逐行节点；详情一次批量取节点，执行每次处理一项有独立事务的任务 |
| 超时 | DB/Redis/队列和执行器传递 context；调用限时、租约心跳、有限停机排空 |
| 权限 | 登录+pod:studio:access+本人有效工作空间；写事务复核，Worker 领取时复核成员 |
| 错误 | response/BizError；不返回 SQL、磁盘路径、Token、供应商密钥 |
| JSON | camelCase，ID/revision/额度为十进制字符串，列表 rows/total，单项 data |

## 执行边界

- 启用方式为 `pod.execution.mode: simulation`，默认关闭；只接受测试执行器。
- 文本输入、图片输入和测试文本节点可执行；真实生图、图片处理、商品预览和导出在后续阶段接通，执行请求遇到它们明确拒绝。
- 整条运行固定项目 revision 和图快照。单节点执行仅使用同项目、同 revision 的既有成功上游输出，缺少时拒绝，不重跑上游。
- requestId 绑定完整请求内容；同键同内容返回原运行，不同内容返回 409。失败恢复有独立请求键，复用成功节点；不允许将待确认调用当作普通失败重提。
- 运行及其素材引用长期保留，项目改图/删除不改变历史快照，也不能删除历史运行依赖的素材。

## 可靠投递、并发与账本

- MySQL 为事实来源，提交事务同时写运行、预占、节点和 outbox。Redis/Asynq 只负责唤醒。
- outbox 持续重投非终态运行，即使队列丢失或入队后进程退出，也可再唤醒；重复消息由节点租约和随机 fencing token 拦截。
- 全局短事务门闩协调领取、余额及限额检查；不在持锁期间执行供应商。限制全局、用户、供应商并发及待处理运行数量。
- 初始测试额度只发放一次并记流水；测试文本节点每次成功消耗 1 单位。预占、结算、释放以唯一事件键落同一事务，整数计数，余额不得为负。
- 租约到期的已领取调用进入待确认，先按稳定请求键查询测试执行器，禁止直接再次 Submit。测试执行器支持按请求键查询；真实供应商不自动继承这个保证。
- 取消停止未领取节点；已领取调用先收尾确认再结算，不承诺强停或无条件退款。
- Worker 停止领取后有限排空；强杀遗留由租约恢复。测试模式的不确定状态可按稳定键查询确认，界面全程标注测试。

## 验收范围

覆盖重复请求/投递、余额竞争、并发限额、固定快照、失败阻断与恢复、取消、租约失效、陈旧回写、队列丢失后的重新投递、跨用户与撤权、历史素材引用、单节点上游复用和流水守恒。
实际网络队列与独立 Worker 另做本地冒烟；不把测试文本输出称为真实 AI 结果。浏览器与 Linux 验收分别记录实际结果。
