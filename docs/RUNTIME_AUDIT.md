## 2. 当前结论

当前已知待修问题为 **P1 0 项、P2 0 项、P3 0 项**。路由与权限标识 130/130 对齐，130 条

## 3. 本轮收口结果

- 用户、角色、岗位、参数、部门、菜单分别用进程内领域锁覆盖唯一性检查到数据库写入；用户
  自助注册、导入、个人资料修改复用用户锁。六类并发新增测试均只允许一个请求成功。
- 密码长度统一按 Unicode 字符数；上传只向客户端返回白名单校验错误，文件系统错误仅记
  内部日志；用户状态严格限制为 `0/1`，登录只允许 `0`。
- 普通账号禁止写入保留角色 ID 1；分页 OFFSET 溢出时饱和而不回绕；JWT 解析固定 HS512，
  同密钥签发的 HS256/HS384 也拒绝。
- 生产配置在副作用启动前校验端口、Gin mode、Redis DB、日志等级和 CORS 来源；导出限流器
  有安全默认容量。任务重复注册和非法硬编码限流参数保留 panic，因为它们是编程错误而不是
  运行期配置输入。
- HTTP 监听失败也执行 HTTP、异步池、调度器的完整关闭流程；缓存键列表达到 500 条后用
  成功终止哨兵停止后续 SCAN；CORS `*` 模式不回显 Origin 且绝不允许 credentials。

业务唯一性方案只对单个 Go 进程成立。若以后启动第二个进程，P2-1 自动重新打开，必须先
改用数据库唯一约束或可靠的跨进程锁；不能把当前“0 项”结论外推到多实例。
