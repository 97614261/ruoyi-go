## 3. 本轮收口结果

- 用户、角色、岗位、参数、部门、菜单分别用进程内领域锁覆盖唯一性检查到数据库写入；用户
  自助注册、导入、个人资料修改复用用户锁。六类并发新增测试均只允许一个请求成功。
- 密码长度统一按 Unicode 字符数；上传只向客户端返回白名单校验错误，文件系统错误仅记
  内部日志；用户状态严格限制为 `0/1`，登录只允许 `0`。
- 普通账号禁止写入保留角色 ID 1；分页 OFFSET 溢出时饱和而不回绕；JWT 解析固定 HS512，
  同密钥签发的 HS256/HS384 也拒绝。
- 生产配置在副作用启动前校验端口、Gin mode、Redis DB、日志等级和 CORS 来源；导出限流器
  有安全默认容量。任务重复注册和非法硬编码限流参数保留 panic，因为它们是编程错误而不是
  运行期配置输入。
- HTTP 监听失败也执行 HTTP、异步池、调度器的完整关闭流程；缓存键列表达到 500 条后用
  成功终止哨兵停止后续 SCAN；CORS `*` 模式不回显 Origin 且绝不允许 credentials。
- 用户、角色、岗位、部门、菜单的关联检查与删除前引用检查纳入相同领域锁，字典类型和字典
  数据统一使用字典锁；多领域固定按用户、角色、岗位、部门以及角色、菜单的顺序获取。
- 角色变更先从数据库取当前成员，再按用户会话反向索引刷新，不扫描全站会话；索引 Pipeline
  每批最多 200 个用户，会话 MGET 每批最多 100 个，用户/部门/角色/权限按固定查询数批量加载。
- 角色权限变更在写数据库前固定成员并推进持久 Redis 权限版本，任一步失败都不提交数据库；
  鉴权发现旧版本后懒加载并 CAS 刷新，进程崩溃或普通重启不会恢复旧权限。进程内补偿只负责
  清理 key，限制为 100000 个 pending、每批 200、20 条错误详情并指数退避到 5 秒。
- 定时任务新增由服务端清空 `jobId` 并强制暂停，不能用 `monitor:job:add` 绕过独立的启用权限；
  `misfirePolicy` 缺省值按 Java 字段初始值设为 `0`。新增、修改、状态、删除、立即执行共用 job
  领域锁，数据库与内存调度器按同一线性顺序变化；非法枚举被拒绝，阻塞并发测试验证锁的
  实际覆盖范围。
- 在线用户 5000 上限按 SCAN key 计数，损坏会话和过滤零命中都不能遍历完整 Redis；Go 仓库
  自带独立契约 manifest，普通单测始终核对，兄弟 Java/Vue 存在时再做三方双向比较。
- 七个代码配置键、Vue 使用的十个字典类型以及既有菜单权限标识禁止无迁移改名或删除；有
  明确格式的配置值同时做写入校验和运行时兜底校验，历史非法值不再静默关闭安全功能。
- MySQL DSN 强制 `parseTime=true` 和上海时区；未被实现消费的 JWT header、非法验证码类型
  在启动前拒绝；操作日志响应捕获最多保留 2000 字节，并在中文边界保持合法 UTF-8。

业务唯一性方案只对单个 Go 进程成立。若以后启动第二个进程，P2-1 自动重新打开，必须先
改用数据库唯一约束或可靠的跨进程锁；不能把当前“0 项”结论外推到多实例。

不能误写成全部行为完全一致。
