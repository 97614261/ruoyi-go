# 图片制作 1—3：使用方法与测试报告

日期：2026-11-12。范围为本机图片处理、去背景/高清放大、T 恤二维预览；本轮不开发个人模板库或批量任务。

## 1. 已实现

| 功能 | 当前行为 |
|---|---|
| 裁剪与旋转 | 设置比例区域裁剪，支持 0/90/180/270 度；先旋转再裁剪，不接受越界区域；当前是参数输入裁剪，尚非鼠标拉框 |
| 调整尺寸 | 保持比例放入指定最大宽高，不拉伸；处理输出最长边 8192、最多 2400 万像素，另受素材文件大小限制 |
| 去背景 | 纯色模式只去掉从边缘连通的相近底色；AI 模式使用 rembg/u2netp 真实本机 CPU 推理 |
| 放大 | 2 倍/4 倍；普通模式为 Catmull-Rom 插值，AI 模式为 FSRCNN 真实超分，不承诺恢复不存在的细节 |
| T 恤预览 | 原创 1000×1200 二维正反面预设，可拖动印花、用方向键/滑条调整位置和大小、选择底色，配置随画布保存 |
| 文件导出 | PNG 保留透明，JPEG 铺白底；印花原图、商品展示和普通图片分别导出、命名；不支持 WebP 导出，旧配置执行前会提示 |
| 尺寸检查 | 印花导出按像素和目标毫米计算有效 DPI，低于 150 给提示；不会修改一个标签就宣称提高清晰度 |
| 结果与来源 | 节点及运行详情可预览、下载；结果作为私有派生素材保留原图、父素材与历史引用；效果图不能重新选入后当印花导出 |

使用现有 `/pod/runs` 和 `/pod/assets`，沿用功能权限、个人空间、固定快照、租约、取消/恢复及鉴权下载。
每个节点按顺序处理 1—8 张输入；中断归档恢复复用已完成图片，不重复创建第一张素材。
没有新增 SQL 迁移，仍为 001—005；没有改管理端 `web/`，未提交 Git。

## 2. 最短使用步骤

1. 打开 `http://127.0.0.1:5177/`，使用本地创作者账号登录，密码位置为 `.local/accounts.json`。
2. 新建或打开项目，左侧“工作流预设”选择“已有印花做 T 恤”。这是内置预设，插入后不会自动执行。
3. 图片输入选择素材，选中图片处理节点，在右侧选择去背景方式；也可换成裁剪、旋转、尺寸调整或放大。等顶部显示已保存后执行。
4. 选中商品预览节点，在右侧拖动印花，设置正反面、底色和大小。上游有可用结果后可看到印花参考，修改后等待保存再执行预览。
5. 印花导出连接处理结果，商品展示导出连接 T 恤节点，分别执行后在节点结果或运行详情下载。印花需要透明底时选 PNG。

结果来源由服务端数据库检查。已经套上 T 恤的展示图，即使重新选入或调整尺寸，也不能当作印花原图再次导出。
只包含已有图片和本地制作节点的流程不调用千问；选择执行分支时，上游 AI 生图/润色会重新执行并可能收费。

## 3. 本机 CPU AI

当前已安装 Python 3.10 独立虚拟环境和固定权重，服务只监听 `127.0.0.1:18112`。
启动脚本先等待模型服务就绪，再启动 API、Worker 和创作端；停止时按已记录进程身份核对。
安装步骤、依赖和权重来源见 [本机 AI 说明](../scripts/image-ai/README.md)。

本机实际验证 `onnxruntime==1.20.1`；1.23.2 曾无法初始化。rembg 和 contrib 共用 cv2 命名空间，
安装依赖后最后重装 contrib 的命令已写入安装说明。环境和权重均在忽略提交的 `.local`，不随 Go 可执行文件分发。

服务不保存图片、不自动下载模型；启动复核权重 SHA-256，只接图片字节，不接图片 URL、文件路径或命令。
Go 侧只接受字面回环 HTTP 根地址，禁代理/重定向，AI 并发 1、单次请求上限 120 秒。
没有配置 AI 时界面禁用选项；服务失败明确报错，不回退成普通算法冒充 AI。
