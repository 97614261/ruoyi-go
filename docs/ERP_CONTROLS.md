# ERP控制流程与本轮验收边界

适用：erp分支、独立本地ruoyi_go_mt库及自有web前端。原Java/main数据库、参考Vue和密码不修改。

## 1. 基线与备份

本轮修改前的已验证最小闭环保存为本地提交`41728d0`，未推送远程。
物理备份使用mysqldump单事务，恢复到唯一命名的新库；校验表结构、每表行摘要、附件大小和SHA256。
不覆盖源库、不FLUSH共享Redis、不启动恢复副本中的定时任务。恢复应用验证使用独立临时Redis。
业务备份和日志只留本地忽略目录，不进Git。浏览器构建/模块HTTP成功不等于实际交互验收。

## 2. 草稿编辑

`PUT /erp/{type}/{documentId}`，提交当前`version`和完整草稿内容，只允许DRAFT。
每次编辑和状态变化推进版本；同版本并发编辑只有一个成功，重复终态动作不推进版本。
仓库/SKU/数量/备注及关联均重新验证；退货原单和reversal类型不可改，需取消重建。
原创建requestKey/requestHash永久保留；用原创建请求重试仍返回同一单据的当前内容，不会覆盖编辑或新建第二单。
单据头和明细在同一只读一致快照读取，避免旧版本配新明细。编辑后请重新打开详情核对。

## 3. 退货与整单冲销

| 页面/类型 | 原单要求 | 过账效果 |
|---|---|---|
| salesReturn / SR | SALE且SHIPPED | 增加实物，不改变预占 |
| purchaseReturn / PR | IN且POSTED | 减少可用实物，不得挤占预占 |
| reversal=true | 上述原单尚无已过账退货，全部原SKU和原数量 | 按对应SR/PR整单反向过账 |

输入在普通单据格式上增加`sourceDocumentId`和可选`reversal`，备注必须说明原因。
仓库必须与原单相同，SKU必须来自原单；快照沿用原单名称/规格/单位，不随当前商品名变化。
可退=原数量−所有已过账退货/冲销数量。草稿不占可退额度，确认时再次复核。
多个员工确认不同退货草稿时，先锁原单，禁止共同超退；取消草稿不产生库存流水。
原单和原流水保留，不改原数量/终态；当前不支持对SR/PR/COUNT再做冲销，也不包含金额、退款或批次追踪。
停用仓库/SKU仍允许依据历史原单纠错，不解除企业状态、仓库范围、可退数量及可用库存约束。

## 4. 盘点

COUNT输入每行`{skuId,countedQuantity}`，实盘必须显式提供，允许0，不允许负数/小数；原因必填。
保存或编辑草稿时，服务器在仓库锁下记录账面onHand、reserved和库存version，客户端不能指定这些快照。
确认时三项都必须一致；有过出入库、预占、释放、盘点，即使实物数量往返到原值也拒绝旧快照。
拒绝后需重新核对实盘，再编辑草稿刷新快照。实盘不能小于当前预占。
过账以差异写COUNT流水（包括零差异确认），余额/流水/单据状态在同一事务；没有直接覆盖库存接口。
盘点只影响选中的1—100个SKU，不代表整仓未选SKU均为0。

## 5. 仓库权限

- 权限链：功能权限 ∩ 当前企业 ∩ 可访问仓库。拥有菜单或同属企业不等于拥有全部仓库。
- 当前企业所有者拥有全部仓库；员工默认空范围。不能通过历史ID、角色名、客户端tenantId/userId或平台身份绕过。
- 所有者在仓库页授权弹窗选择员工和仓库；列表分页，跨页保留选中项，最多200个，空集合表示全部撤回。
- 前端busy覆盖确认框与保存全过程，确认前固定目标员工、版本、仓库快照；取消/错误不能提示成功。关闭后重开或切换员工时，旧异步范围响应不得回填。
- GET/PUT `/erp/warehouse/access/{userId}`要求`erp:warehouse:grant`和实时所有者校验；PUT必须当前授权version。
- 范围替换、版本推进、成功审计同事务；失败全部回滚。新所有者以sys_tenant.owner_user_id为准，旧所有者不保留隐含全仓权限。
- 业务写入和范围替换都锁目标员工；撤回后同一旧会话不能再读写该仓库，不依赖重新登录/缓存过期。
- 列表、详情、草稿编辑/确认/取消/出库/纠错、余额/流水和既有仓库导出都过滤。跨仓库移动草稿在锁内再次校验权限。
- 仓库主数据创建/修改/删除仅限所有者。SKU是企业级共享商品目录，不按仓库隐藏；店铺权限不在本轮。

## 6. 显式升级

```powershell
# 先备份，仅允许独立本地库。001保留，002只增加ERP字段、索引/约束及两张授权表。
go run ./cmd/erpinit -config configs/multitenant.local.yml
# 默认只登记菜单定义，不为任何现有企业或员工开通。
```

MySQL 5.7 DDL可能隐式提交，失败时保留备份并检查已完成对象，不假装事务回滚了DDL。
重复运行只补缺失对象并复核结构；发现同名异构须人工处理。服务器启动只读检查，不自动迁移。
不要未经确认运行`-grant-demo`：它会向demo/demo-b追加全部当前ERP节点并使旧会话失效。
用户再次确认收尾后，2026-10-20已只为demo/demo-b追加本轮ERP节点，保留历史权限和默认仓库；未额外给员工分配角色或仓库范围。
其他企业仍由平台功能授权显式选择；企业管理员还要单独配置员工角色功能和仓库范围。

## 7. 并发与验证

写事务：当前员工→原单（若有）→当前单据→仓库→排序SKU/余额。库存余额、流水、状态原子提交。
纠错写事务使用READ COMMITTED，配合原单排他锁读取最新分组SUM；结果不超过原单SKU数，不把全部历史退货明细载入内存。
当前仍有员工/仓库粗粒度串行边界，不能把正确性测试当吞吐、最大用户数或多实例认证。
