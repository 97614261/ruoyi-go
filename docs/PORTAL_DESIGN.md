## 2. 技术与部署

| 部分 | 选择 | 说明 |
|---|---|---|
| 门户前台 | Gin + Go `html/template` | 服务端返回含正文的完整 HTML |
| 样式与交互 | CSS 变量、响应式 CSS、少量原生 JS | 不依赖前端运行服务；首期不设 JS 构建链 |
| 内容后台 | 独立 `admin-web/`，Vue 3 + Element Plus | 从参考后台建立自有副本，新增 CMS 管理页面 |
| 业务与数据 | 现有 Go 分层、GORM、MySQL | 复用账号、角色、权限、日志；CMS 独立新表 |
| 缓存 | 先复用 Redis 做访问保护；页面缓存按实测引入 | 下架和发布语义先正确，不预先叠加缓存复杂度 |
| 部署 | 一个 Go 进程，可加 Nginx | Go 可嵌入门户模板/静态资源/已构建后台；上传附件单独持久化 |

Node.js 仅用于开发机/构建机编译 Vue 管理后台，运行服务器无需安装 Node.js。
`main` 没有 ERP 分支的自有 `web/`，不能把 ERP 工作区当成门户初始代码。
参考目录 `../RuoYi-Vue3-master` 不修改；自有副本须保留上游许可证及必要声明。

生产可用 Nginx 提供 TLS、代理 Go；没有 Nginx 也能由 Go 提供页面和静态文件。
资源/内存/并发容量须实际压测，不按框架名称承诺适合多少用户。

## 3. 页面与后台菜单

### 访客页面

| 页面 | 建议路由 | 内容 |
|---|---|---|
| 首页 | `/` | 导航、轮播、介绍、推荐文章/产品、页脚 |
| 新闻栏目/详情 | `/news`、`/news/c/:slug`、`/news/:slug` | 分类、分页、封面、摘要、完整正文 |
| 产品栏目/详情 | `/products`、`/products/c/:slug`、`/products/:slug` | 分类、图片、简介、参数、详情；不含下单 |
| 单页 | `/p/:slug` | 关于我们、联系我们、服务介绍等 |
| 搜索 | `/search?q=...&page=...` | 仅公开内容，限制关键字长度和分页深度 |
| 搜索引擎入口 | `/sitemap.xml`、`/robots.txt` | 仅公开、规范化的网址 |

每页有独立标题、描述、规范 URL；失效内容返回真实 404，错误返回 500/503，绝不伪装成成功正文。
首期采用短而稳定的英文 slug，校验保留词并设置同类唯一约束；已发布 slug 首期禁止直接修改，
后续有重定向表和迁移测试再开放改名。分页、栏目和内容查询使用明确的唯一兜底排序。

### 管理后台：门户管理

| 菜单 | 能做什么 |
|---|---|
| 栏目管理 | 新闻/产品栏目，层级、名称、排序、启停及栏目 SEO |
| 文章管理 | 标题、封面、摘要、正文、作者、推荐、草稿/预览/发布/下架 |
| 产品展示 | 产品名称/编号、封面、图集、简单参数、正文、发布/下架 |
| 单页管理 | 关于我们、联系我们等固定页的内容与发布 |
| 导航与轮播 | 页头/页脚链接、首页轮播、排序、启停；内部内容用 ID 引用 |
| 素材管理 | 上传图片、替代文字、使用位置、未被引用的素材清理 |
| 站点设置 | 名称、Logo、联系方式、页脚/备案信息、站点 SEO 默认值 |
| 模板与外观 | 选模板、调整样式、区块开关、预览、发布和恢复上一版 |

内容编辑员负责编辑；内容发布员有独立发布/下架权限；站点管理员管理外观和设置。
权限按 `cms:article:*`、`cms:product:*`、`cms:page:*`、`cms:channel:*`、`cms:asset:*`、
`cms:site:*` 登记，`publish` 与 `edit` 分开。所有 CMS 管理接口都经过现有鉴权和对应权限。
自助注册不自动授予任何 CMS 权限。本期不新增门户会员身份。

## 4. 模板切换与样式配置

### 两套内置模板

- `business`：企业官网布局，突出介绍、产品、服务和联系方式。
- `editorial`：资讯门户布局，突出栏目、文章、推荐和阅读。

两套模板都必须支持首页、栏目、文章、产品、单页、搜索、空状态和错误页，手机端均可使用。
共享一个明确的 `PortalPageData` 数据协议，正文和栏目不写死在模板里。
模板名称由注册表解析，不能把用户提交的名称当作文件系统路径。

每套模板自带 `manifest.json`，声明模板 ID、资源版本、数据协议版本、必需页面、默认配置、
可选首页区块和配置约束。启动时按模板分别解析，避免同名 `define` 相互覆盖；预解析后只读执行，
不能在每个请求中修改一个共享的全局模板。

### 可调外观

- 主题色、辅助色、浅/深外观（仅当该模板声明支持）。
- Logo、站点图标、预设字号、圆角档位、内容宽度档位。
- 首页区块显示/隐藏、顺序、对应栏目与条数；每个区块有数量上限。
- 页头、页脚、轮播和联系方式。

使用白名单配置转换成 CSS 变量和页面数据，不保存任意 CSS、脚本、Go 模板或 HTML 代码片段。
第一版使用表单和上下移动按钮配置首页区块，不做自由拖拽排版。
不兼容的设置须在预览/发布前说明，不能换模板时悄悄丢配置。

### 预览、发布、恢复

1. 选择模板和调整配置，保存为外观草稿，线上版本保持不变。
2. 后台发带现有登录凭证的预览请求，得到预览 HTML，在隔离 iframe 中展示；不把 JWT 放进 URL，
   不把草稿文件写进公共静态目录。预览页面 `no-store`、`noindex`，与公开页面缓存分开。
3. 发布前校验模板完整性、配置、栏目/内容/素材引用和版本；失败保留当前线上版本。
4. 事务创建不可变外观版本并更新站点当前版本指针。并发旧版本发布返回冲突，页面加载只用同一份版本快照。
5. 恢复上一版实际是把历史配置作为一个新版本发布，也要重验引用、权限和版本。

外观恢复只恢复模板/样式/导航/轮播，不恢复文章、产品、栏目状态、文件和数据库。
历史版本引用已下架内容或不可用素材时必须提示处理，不能借恢复操作重新公开。
旧模板资源保留到历史版本不再依赖它；新增模板代码仍需部署，切换已有模板和外观不需重新打包。

## 5. 内容发布规则

内容分为工作草稿和已发布修订版。编辑已发布文章时，访客继续看到原修订版，直到显式发布新稿；
不能用一个 `status` 字段配合直接覆盖正文，导致“保存草稿”实际上更新线上内容。

文章、产品、单页共享不可变修订机制；发布事务切换公开修订指针，下架清空公开状态但保留历史。
公开列表、详情、搜索、推荐、导航和站点地图统一经过“当前可公开”过滤；栏目停用后关联入口也隐藏。
首页等聚合结果必须批量读取，禁止按卡片循环查数据库。

第一期不提前缓存完整 HTML；后续若加缓存，必须把版本纳入键，并在返回前核验当前发布状态，
覆盖下架/旧请求回填/并发切换测试。不能只靠短 TTL 接受下架内容继续公开。

普通文本使用 `html/template` 默认转义；富文本通过项目现有净化能力和门户允许元素策略处理后，
才在一个受控的渲染入口转换为可信 HTML，不提供任意“safeHTML”模板函数。
外部链接限定安全协议；图片限定已登记素材来源；预览、搜索词、标题和配置也要测试注入边界。

## 6. 数据与资源设计（候选，不是已执行 SQL）

采用独立开发库 `ruoyi_go_portal`，从核准的单租户基线初始化。数据库账号、Redis DB/命名空间、
上传根目录、HTTP 端口和定时任务开关均与原库/ERP 分开。开始建库前须再核对实际本地配置和备份。
本次没有创建或连接新库。原 `main` 的生产结构冻结规则不因建门户而失效。

| 候选表 | 用途与关键字段 |
|---|---|
| `cms_site` | 单站点配置入口；当前外观发布版本、CAS version |
| `cms_site_release` | 模板 ID/资源版本、样式/导航/轮播/区块 JSON、配置协议版本、发布人/时间；不可变版本 |
| `cms_channel` | 栏目类型、父级、名称、slug、排序、启停、SEO、CAS version |
| `cms_content` | 类型 article/product/page、稳定 slug、栏目、草稿/公开修订指针、公开状态、CAS version |
| `cms_content_revision` | 不可变内容快照：标题、摘要、正文、封面/图集、产品参数、SEO、修订号 |
| `cms_asset` | 存储标识、文件类型/尺寸/大小、替代文字、上传者、创建时间 |
| `cms_asset_ref` | 修订版/外观版本与素材的精确引用关系，防止误删及草稿泄露 |

正式 SQL 阶段细化列类型、外键与索引；所有表保留项目标准审计字段。类型取固定集合，列表分页，
查询上限沿用 pageSize≤100。发布/保存 CAS、slug 唯一性、引用清理应由数据库约束和事务保障。
公开查询需按栏目/类型/公开状态/时间/ID 建候选复合索引，再用种子规模和 EXPLAIN 验证；
第一期检索用有界参数化查询，只扫已发布标题/摘要，不直接对长正文做无界模糊扫描。
内容量达到门槛后再按中文检索效果和实测评估全文搜索，不预装搜索服务。

正文图片初始位于门户专用非公开存储，后台通过鉴权预览访问；只有被有效已发布修订/外观引用的素材
才允许走公开 `/media/:id`。公共响应状态、ETag/304也必须在公开引用校验之后决定。
私有文件不放进现有匿名 `/profile` 根目录；无法撤销访客已经下载的副本，不把服务端下架说成远程删除。
后台清理前检查全部草稿/历史/当前引用，只允许删除没有引用的文件，并记录审计。

CMS 新表放 `sql/portal/`，显式执行升级，启动只读校验，不自动迁移、不修改原 sys 表列/索引。
新增 CMS 菜单属于新定义，不能自动扩大既有账号权限；初始化测试用户和角色须限定新门户库。

## 7. 代码组织与路由边界

```text
portal/                         # Go资源包，可嵌入发布文件
  themes/
    business/                   # manifest.json、templates/、static/
    editorial/
  admin-dist/                   # 构建生成，不手写
admin-web/                      # 自有 Vue 管理后台源码
internal/model/cms_*.go          # CMS实体、请求、公开页面DTO
internal/repository/cms_*.go     # 只有这里操作数据库
internal/service/cms_*.go        # 发布、预览编排、公开内容聚合
internal/handler/cms_*.go        # 管理接口
internal/handler/portal_*.go     # HTML页面与公开素材
internal/router/portal.go        # 路由与鉴权登记
pkg/portalview/                 # 模板注册、校验、受控渲染；不查库
sql/portal/                     # 显式迁移与新菜单定义
```

管理后台入口 `/admin/`；CMS 管理 JSON 接口 `/cms/...`，继续走现有 `pkg/response`。
后台构建时同步设置资源基础路径和 Router base；现有 `/login`、`/system/*`、`/getInfo` 等 API 保留路径。
SPA fallback 仅处理 `/admin/` 内非资源导航，不能吞掉 API、门户 404、健康检查或缺失资源。
门户新 HTML、预览 HTML、XML、文本及公开素材按各自 Content-Type/HTTP状态输出；
为此在门户分支登记新的响应边界，不能把历史“业务 JSON 200”规则强加给公开网页，也不能改旧接口状态。
HTML 先渲染到受限缓冲后发送，模板执行失败不能返回半截成功页面；日志不暴露草稿正文和凭证。

普通资料 CRUD 优先使用现有生成器生成到自有后台目标；发布/版本/模板切换必须由专用业务服务实现，
不能仅生成一个任意可写的 revision/published 指针 CRUD。只有 repository 访问数据库，继续按 handler → service → repository 分层。
