## 故障和刷新验证

| 场景 | 验证方式及结果 |
|---|---|
| 请求超时、断网、供应商 408/500、返回格式不明 | 替身请求保留待确认，原调用不自动重发，凭据不出现在错误中 |
| 客户端提交失败后重新打开 | 恢复原请求 body/requestId，未新建第二个请求 |
| 两张图中的第二张下载失败 | 第一张归档保留；新建执行器模拟重启后只重试第二张下载 |
| 部分归档恢复后的调用次数 | 模型调用 1 次；第一张下载 1 次、第二张下载 2 次；两个不同素材及 0.20 元估算用量保留 |
| 服务端已归档、完成回写丢失 | 复用持久调用和素材映射，不再次生图 |
| 润色处理中页面组件被销毁后重建 | 读取原运行并恢复结果，不再次 POST，不再次保存/调用 |
| 润色完成但尚未决定是否替换 | 重建组件仍可预览；用户确认前不自动覆盖文字 |
| 两张图结果在组件重建后恢复 | 两个素材均恢复，继续使用原运行，没有再次生成 |
| 原文在等待期间改变 | 旧润色结果不能覆盖新文字 |
| 重复任务投递、Worker 中断恢复 | 原有真实 Redis 队列与子进程故障回归继续通过 |

刷新证据来自前端组件销毁/重建、本地存储恢复、真实 API 重新读取及幂等重复提交。
本轮浏览器仅确认本地登录页正常，没有完成已登录页面的真实刷新/手机操作验收；不得把组件测试描述成浏览器实测。
供应商真正响应丢失时，若不能查明原调用结果，仍保持待确认并保留预占，需要人工核对供应商明细；不保证能自动恢复未知结果。
