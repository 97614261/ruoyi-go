## 企业与账号

- 租户代表签约、付费、数据隔离的客户工作空间，不等于某一家店铺或一个部门。
- 一家客户可有多家店铺、多仓库、多部门。需要“集团/法人/财务主体”时在租户内增加组织实体，不混用tenant_id。
- 目前用户属于一个企业；同一自然人跨企业切换是后续身份体系能力，本轮不靠切换前端tenantId实现。
- 平台超级管理员管理企业生命周期与开通范围，不获得读取全部客户订单、成本或店铺凭据的免过滤权限。

## 业务设想与当前实现状态

下表区分已有与未实现；一期仅选店铺、配对、订单、包裹及导入的基础履约，其余不是自动承诺的实施范围。

| 模块 | 主要实体 | 当前状态与后续边界 |
|---|---|---|
| 基础资料 | 商品、SKU、计量单位、供应商 | SKU及供应商已实现，同企业编码唯一；供应商联系人仅详情权限可读，独立单位目录未实现 |
| 店铺商品 | 店铺可售变种、外部标识、SKU配对 | 已实现手工维护/启停、版本化配对/解绑和历史保护；非SPU、组合商品、平台刊登或自动同步 |
| 店铺 | 店铺、渠道授权、同步任务 | 店铺资料/启停/员工范围和只读渠道目录已实现；无真实渠道授权、同步或凭据保存 |
| 仓库 | 仓库、库区、库位 | 仓库和员工范围已实现；库区/库位未实现，后续关联同样带tenant_id |
| 订单 | 订单、订单明细、状态事件、单包裹 | 手工/模板接单、待审编辑、审核预占、取消、手工运单与本地发货已实现；来源键按企业+店铺隔离，无拆合单/售后/平台API |
| 库存 | 库存余额、预占、出入库单、不可变流水 | 手工闭环已实现；批次/库位扩展未实现，不能直接覆盖余额冒充盘点 |
| 采购 | 供应商、采购订单、分批收货 | 目录/草稿、精确报价快照、确认/取消/关闭、分批入库及三页已实现，进度与库存同事务、无价格DTO独立授权。完整两轮及所有者/员工GUI本地通过；无采购退货、应付或成本核算 |

本地手工库存闭环已实施：SKU→仓库→入库→销售出库单→预占→出库→释放/扣减，并支持限定的纠错/盘点。
旧销售单仍是库存凭据；新商业订单单独保存收件/原始金额等信息，通过事务履约托管库存凭据。手工物流不等于真实平台/承运商API，仍无收款/结算/利润核算；不把“有页面”当成完整电商ERP。

## 数据与并发规则

1. 业务表带tenant_id和审计字段；所有唯一键、业务外键都考虑企业，复合关联不得串租户。
2. 先设计DDL和约束，再用现有生成器生成CRUD，人工补领域事务与校验；生成器不是订单/库存状态机。
3. 订单状态只允许显式流转。取消订单同时释放预占，重复请求凭幂等键返回同一结果。
4. 库存使用整数基础单位或明确小数精度，金额使用定点数；不使用float64处理钱和需要精确的数量。
5. 库存余额行按企业+仓库+SKU（必要时批次/库位）定位并加锁；流水与余额同事务提交。
6. 同企业内部还要检查店铺/仓库/订单权限，不能把“同租户”当作所有员工均可访问全部资源。
7. 客户端不得选择tenant_id；异步同步任务、导入、导出和附件同样保留服务端企业上下文。
8. 渠道同步先保存幂等事件，再应用业务变更，失败可重试、可追踪；不先引入消息中间件替代基本事务设计。

## 分支协作

- 通用租户能力和通用修复：multi-tenant开发、验证、提交，再合入erp。
- ERP专属代码与DDL：只在erp；可复用抽象经过验证后再回提，不把ERP字段塞进用户/部门表。
- main修复若通用，评估后分别合入；main、multi-tenant、erp不是自动继承关系。
- ERP已新增独立业务表；本轮不推送远程，也不把ERP业务表反合到multi-tenant/main。精确版本以git log/branch为准。

## 开发验收与正式上线的剩余边界

- 已补ERP员工授权/撤权、旧会话拒绝、失败内容保留和重试的实际页面证据；其他页面是否验过按对应报告逐项判断，不从该链路外推全部平台页面均已验收。
- 库存仍为整数基本单位、禁止负库存，不包含金额成本；采购单已独立保存单币种精确报价，但无汇兑、多币种核算、多法人、批次/序列号或财务能力，不能混作库存成本。
- 专用企业备份/恢复应用与附件隔离已通过；原demo凭据及原账号恢复核验经用户决定延期，不能相互替代，历史轮次结果见测试报告。
- 生产库迁移、生产容量、渠道合规与商业套餐不属于本轮已完成项。
