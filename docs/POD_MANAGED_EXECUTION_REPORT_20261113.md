## 已实现及入口

| 位置 | 行为 |
|---|---|
| 创作端节点卡片/参数 | 从本人已授权且可用的模型中选择，显示实际版本和能力限制 |
| 执行、润色、分支、恢复及批量确认 | 服务端报价列出模型/版本和最多预占点数，用户确认后才提交 |
| 运行与批次详情 | 显示本次预占、已用及释放；点数采用十进制字符串和整数计算 |
| 运行与用量 → 正式点数 | 查询本人正式点数账户和分页流水 |
| 资格与点数 | 查询本人资格、限额、授权模型数、正式点数及流水 |
| 管理端 → 创作者管理 → 详情 → 点数与流水 | 区分人工发放/扣减、预占、结算、释放和转移 |

报价有效 10 分钟，每位用户最多保留 20 个有效未消费报价。报价固定来源版本、模型版本、价格和权益版本；
输入或配置变化后需要重新报价。创建请求的幂等键及摘要固定，提交结果未知时核对原报价与原请求，不能换编号重复提交。
模型列表只返回选择所需字段，不暴露 endpoint、成本价格、凭据或供应商原始响应。

既有 `pod_creator` 没有自动获得目录中的真实模型或正式点数，因此页面显示“暂无已授权的可用模型”是正确的授权结果。
要启用真实生成，需要管理员明确配置目录凭据/模型、授权用户并发放点数；本次未执行这些操作。

## 计费与恢复边界

- 创建运行时事务预占所需点数；批次先预占整体，派发按每项额度转移，停止只释放未派发份额。
- 新供应商调用前持久化意图、成本预占和点数分配。确认回执与结算原子提交，重复处理不重复扣点。
- 未知调用保留成本和点数预占，不自动重发，不按 TTL 释放；部分图片归档恢复不重新生成。
- 实际供应商用量超出声明上界时保留实际成本证据、停用模型，用户扣点封顶于原预占，不能偷偷超扣。
- 恢复只针对明确失败项，沿用原模型和价格版本，重新报价确认新增份额；成功项不重复收费。
- 权益和模型授权在提交及领取时复核；已提交的调用继续核对、归档和结算，不能因撤权丢失费用事实。
- managed 运行缺失匹配 owner/空间的执行快照时拒绝领取，不能按免费旧任务处理。
- 切换模式后旧请求原键重放返回原记录；新旧模式不符的提交拒绝。Worker 取消未提交步骤，已提交回执继续核对。
- 已确认的旧 qwen 回执可在没有旧 Key 时继续归档；未知回执不重新 Submit。

011 新增报价、执行快照、节点绑定和调用计费四张执行事实表。没有修改已安装的 001—010，也没有把旧任务转换成正式计费任务。
完整接口、表结构与切换流程见 [接口](./POD_PLATFORM_API.md)、[数据](./POD_PLATFORM_DATA.md)、[迁移](./POD_PLATFORM_MIGRATION.md)。
