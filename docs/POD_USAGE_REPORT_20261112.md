# 创作者用量：实现与验收

日期：2026-11-12。用户“继续 4”指后续计划第 4 项；第 3 项批量没有开始。
本轮继续使用本地专用 POD 环境，不修改 web/ 管理前端、继承系统表或已安装 SQL。

## 1. 怎么用

1. 左侧“运行与用量” → “我的用量”，查看本人全部项目的累计估算费用、预占、模型次数和已确认生图数。
2. 每次运行一行，费用包含所有恢复尝试；点“查看运行”回到详情。画布中的入口只打开当前项目的运行。
3. 执行前先核对范围预览：文字次数、生图次数/张数、本地步骤、涉及哪些 AI 上游及逐项预占合计。
4. 预算不足先看用量和预占，由部署者核对实例上限；归档失败等待原下载恢复；未知调用保留运行编号核对，不能盲目重发。

全库预算不是个人余额，不显示“上限减本人消耗”的假余额。预占不等于已扣款；金额为人民币估算，供应商账单为准。
图片数含尚未归档的模型结果，不代表可下载张数；本地处理和模拟图片不计入。测试额度仍为无货币价值的模拟单位。
人工对账的独立权限、审计和幂等要求完成设计，当前没有人工改费、释放未知预占或重发未知调用的写接口。

## 2. 实现与边界

- 新增 GET /pod/usage，data 为 summary/rows/total/budgetScope/budgetLimitMicros，响应 no-store。
- 本人有效空间和成员是必要条件，管理员不能绕过。客户端 userId/workspaceId 不改变查询范围。
- 所有尝试的费用从 pod_provider_call 统计；不依赖可能被恢复覆盖的节点 output。
- 只选取白名单数值，JSON 中的模型图片数仅从 confirmed 记录提取，不读取或返回整个私有响应。
- 只读一致快照、5 秒服务超时、明细最多 100，时间倒序并以唯一 run_id 兜底；当前页批量 GROUP BY，无逐行查库。
- 可使用已有空间/运行及调用 run_id 索引，无索引或表结构变化。全历史统计成本随本人调用增长，本轮未做大规模容量压测。
- 前端金额用字符串和 BigInt，避免浮点舍入；每 10 秒只读刷新用量，卸载停止轮询、换账号/失权清空私有数据，旧响应不能覆盖新身份。
- branch 包含所需祖先、node 只执行目标并要求历史上游、polish 仅一次文本调用。预览不是最终报价，实际服务端校验仍生效。
- 修改图后撤销旧付费勾选；未知提交只重试原版本/原请求，不用当前草稿的范围预览误导用户。
