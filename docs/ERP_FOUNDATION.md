## 1. 先分清已有能力和未提供能力

同一商品从建档、采购/退货到订单/发货/退货，再到应付应收核销的真实HTTP顺序测试见
[业务全链路验收](./ERP_BUSINESS_FLOW_ACCEPTANCE.md)。它补充各模块独立回归，不代替权限、并发或故障测试。
已提交但客户端未收到成功回包时的原请求重试，另见[回包丢失验收](./ERP_UNCERTAIN_OUTCOME_ACCEPTANCE.md)。

| 范围 | 现在怎么用 |
|---|---|
| 企业与账号 | 平台管理企业生命周期、功能开通、配额和所有者；客户管理本企业员工与角色 |
| 权限 | 企业开通范围、员工功能权限、企业隔离共同约束；仓库和店铺分别检查实时资源范围，不能互相替代 |
| 公共能力 | 字典、参数、附件、日志、任务、分页、导出限额、生成器均复用现有实现 |
| 商品主数据 | 企业共享SPU/多SKU、分类、图片、条码尺寸、整批新增模板导入导出；店铺配对另查实时店铺范围，已引用SKU关键字段及商品聚合受保护 |
| ERP 示例 | 仓库资料CAS、单据/库存控制、调拨/预警/追溯与只读核对；店铺为生成器扩展的版本化所有者CRUD，员工授权需另查实时范围；库存变化不能套用普通 CRUD |
| 店铺商品配对 | 一个变种配一个企业内部SKU，员工仍受店铺范围限制；共享商品version防覆盖，配对行停用/复用保留历史，不套用通用DELETE |
| 待审核订单 | 手工录入、编辑、摘要导出、固定XLSX导入；不改变库存，重复输入不覆盖编辑后的订单 |
| 导入任务 | 私有原文件24小时/共享附件配额、逐订单事务及结果、失败/中断显式重试；创建者/当前所有者加实时店铺范围 |
| 事务履约 | 审核按内部SKU汇总预占、固定原行快照并建单包裹；取消释放；维护手工运单后确认本地出库。店铺与仓库范围同时检查，旧库存入口不能独立操作托管凭据 |
| 页面工作台 | 当前范围订单状态统计、所选仓库只读配对/缺货检查、审核快照及订单/包裹/配对互跳；批量最多20条逐单结果/原请求重试，非整批事务 |
| 财务基础 | 008/009内部账户、收货应付/发货应收、原退货抵减、分次/多单核销、整笔记账冲销、范围内对账/导出；不代表真实资金流或完整会计 |
| 企业启用 | 所有者16项只读准备检查、五类新角色模板预览/精确预填、原配置页面跳转；不是自动建账/入库/授权，也不强制个人企业建立员工 |
| 经营概览 | 六区沿原功能与实时范围汇总，按上海自然日/库存记录/毛收货/逐单分币种余额计算，点击进入原列表；不提供收入、利润或银行余额 |
| 运行边界 | 一台服务器、一个 Go 服务进程；这不是“只能一个用户”或“服务器只能部署一个系统” |
| 尚未提供 | 任意生产库自动升级工具、跨企业自然人身份切换、通用审批、消息中间件、完整采购/财务流程 |

通用附件仍默认企业级隔离，不能声称全部附件随单据权限隐藏。订单导入是独立例外：私有兄弟目录、仅业务授权下载，不经/profile；其登记计入现有sys_file容量。其他敏感单据挂附件仍须另行设计。
同理，部门数据权限不等于仓库范围，菜单可见不等于接口已授权，平台身份不能代入客户业务。

## 3. 新增普通模块的固定步骤

1. **先写接口检查单**：分页上限100；索引与搜索方式；无N+1；context/超时；功能及数据权限；统一错误/脱敏；camelCase响应。
2. **先设计并审查独立库的DDL**：`tenant_id BIGINT NOT NULL` 无业务默认值；五个审计字段；企业内唯一键；关联包含企业；有明确删除/停用语义。仅为设计示例，不在本轮建新表。
3. **平台生成器导入实际表**：选择Vue 3模板，设置模块、业务名、权限和字段。`tenant_id` 不出现在新增/编辑/查询控件中。名称应避免与已有文件、路由、菜单ID冲突。
4. **先预览、下载ZIP到临时目录检查**，不要直接覆盖仓库。生成包的 `vue/src/...` 需审查后映射到自有 `web/src/...`，不是参考前端目录。模型、仓库、服务、处理器和路由文件按生成包README放置。
5. **补领域规则**：金额/精确数量不用float；零值不能被required或结构体Updates误丢弃；删除检查引用；涉及竞争时设计数据库事务/约束。请求体的tenantId、userId、状态、审计人不能决定授权。
6. **分开注册、开通、授权**：菜单定义只是登记；平台为企业开通；企业管理员给员工分配角色；资源范围另行授予。菜单SQL也需审查固定ID与权限名，不覆盖现有授权，不默认执行`-grant-demo`。
7. **补测试再验收页面**：跨企业、同企业无权限、伪造归属、分页/零值/长度、错误重试、导出、并发、失败回滚。复杂JOIN、异步任务和附件关联均单独审查。
8. **记录升级与验收证据**：脚本版本、适用库、操作顺序、失败处理、实际结果；扩展后的文件不再用原始生成配置盲目覆盖。

生成器已存在，当前无需另加插件框架。生成器只能产出CRUD骨架，不能生成可靠的库存状态机或自动决定业务数据权限。
单据领域流程直接参考现有ERP实现和锁顺序，不为“复用”先抽象一套任意状态机。

## 4. 一个验证入口，两种明确范围

从仓库根目录运行；Go1.25+、Node和已安装的`web/node_modules`是前置条件。
依赖安装由操作者事先执行，脚本不会自动下载依赖、启动/停止服务或迁移数据库。
Go步骤固定`GOPROXY=off`、`GONOPROXY=none`、`GOTOOLCHAIN=local`、`-mod=readonly`；缺少缓存依赖或本机工具链时失败，先显式准备依赖再重跑，不自动调整模块需求。结束恢复原环境变量，即使写报告失败也执行环境恢复。

```powershell
# 只展示JSON计划：不执行命令、不连接数据库、不生成报告
.\scripts\verify-erp.ps1 -Plan

# 默认：gofmt只读检查、Go单测、vet、前端测试、生产构建
.\scripts\verify-erp.ps1

# 显式追加本地多租户/ERP真实回归（会写入专用验收数据）
.\scripts\verify-erp.ps1 -Integration -Count 2

# 脚本自身的安全边界测试；使用命令桩，不连接产品数据库
powershell.exe -NoProfile -File .\scripts\tests\verify-erp.tests.ps1
```

Go/Node不在PATH时可传`-GoPath`、`-NodePath`；格式工具默认取Go同目录下的gofmt，可传`-GofmtPath`。
默认检查不运行`./test/`旧单租户接口包，也不运行`go test ./...`。原`scripts/test.ps1`保留用于原单租户验证，不是本分支的默认入口。

每次实际执行保留独立的`test/results/erp-<UTC时间>-<随机后缀>/summary.json`和分步骤日志。
失败返回非0并停止后续步骤；未执行写`NOT_RUN`。没要求集成测试时明确写`NOT_REQUESTED`，不能当作集成测试通过。
gofmt只报告不写文件；构建会更新`web/dist`，Go缓存和验证日志也会写入本地忽略目录。

## 5. 什么时候可以说“底座够了”

### ERP弹窗的稳定规则

自有web的ERP弹窗使用`erp-dialog`命名空间及`min(原设计宽度, calc(100vw - 24px))`；高度限视口，标题/底部按钮不跟正文一起滚出屏幕，宽表在内部滚动。共享规则在`web/src/assets/styles/erp-dialog.scss`，不要扩成所有后台弹窗或只在scoped样式里假设Teleport内容一定能匹配。
旧主题的!important顶部间距需命名空间内显式覆盖；栅格负边距不能制造正文横向溢出。新增/初次生成ERP页面后也要接入该规则再运行验证，不能用生成模板盲目覆盖已有领域页面；本轮未修改通用生成器模板。
`erpResponsive.test.mjs`只防源码接线回退，不声称已经渲染；真实浏览器检查仍要验证窗口边界、滚动和实际按钮可达，不能为通过检查而全局隐藏溢出或截图裁掉问题。

### 完成标准

新模块能够沿上述路径开发，并通过企业/功能/资源边界、事务和错误场景测试，就具备继续开发业务的基础。
不以菜单数量或“10分”代替证据。当前已有自动回归和真实页面证据见[ERP_TEST_REPORT.md](./ERP_TEST_REPORT.md)。
部署、升级、恢复的操作边界见[ERP_RELEASE.md](./ERP_RELEASE.md)；生产容量与正式交付仍是单独门槛。
