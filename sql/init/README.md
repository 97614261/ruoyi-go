# 新测试库初始化

适用当前 `erp` 分支。导入 **erp_test_full.sql 一份文件**，不必再按顺序运行旧脚本或 tenantinit、erpinit。

## 包含什么

- 82张表：系统、多租户、配额/附件，以及 ERP 001—011 全部结构和原有约束、索引。
- 完整系统/平台/ERP菜单及按钮权限；ERP菜单分类由当前前端处理。
- 基础字典、系统参数，003—011共9条真实DDL版本及校验和记录；001、002沿原规则不写版本行。
- 平台管理员、两个独立测试企业的管理员；两家企业均已开通客户可用功能和全部ERP功能，各有一个空的默认仓库。
- 商品、店铺、供应商、库存、采购、订单及财务单据从空白开始；没有复制现有开发库的业务、日志、附件、密码或历史测试企业。

最近新增的采购补货复用现有结构，包含在本初始化的支持范围内，无需额外012脚本。

## 怎么导入

1. 新建一个数据库，字符集选 **utf8mb4**，排序规则选 **utf8mb4_unicode_ci**，例如 `ruoyi_erp_test`。
2. 在数据库工具中选中这个新库，运行本目录的 **erp_test_full.sql**。使用“执行SQL文件/脚本”，整份执行，保留 `DELIMITER`。
3. 最后看到 `ERP_INIT_COMPLETE`、`table_count=82`、`migration_count=9`，表示初始化完成。

也可打开MySQL命令行，输入：

```sql
CREATE DATABASE ruoyi_erp_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE ruoyi_erp_test;
SOURCE D:/WorkSpace/go-space/ruoyi-go/sql/init/erp_test_full.sql;
```

脚本不固定库名，使用当前选中的新库。执行账号需要建表、修改表、引用外键，以及创建/执行/删除存储过程的权限。初始化过程会创建临时存储过程，完成后自动删除。

**仅用于新建空测试库。** 脚本主动拒绝非空库、系统库及现有开发库名 `ruoyi_go_mt`，没有删表或删库语句。出现任何错误立即停止；DDL不能靠事务回滚。失败后保留报错，另建空库重试，不在已有业务库或半成品库继续导入，也不要开启“忽略错误继续”。

## 后端怎么连接

先停止当前后端，把已有本地配置复制为 `configs/erp-test.local.yml`，保留其他配置项，修改：

| 配置项 | 要改成什么 |
|---|---|
| mysql.dsn | 数据库名改成刚导入的新库；同时核对账号、密码、地址 |
| redis | 使用另一个未被占用的空Redis DB或独立实例，与现有环境隔离 |
| upload.path | 独立目录，例如 `./uploadPath-erp-test`；不要复用旧附件目录 |
| jwt.secret | 为这套测试环境生成新的随机密钥 |

新库会重新使用用户ID，所以不能只换MySQL库、却继续共用旧环境的Redis会话缓存。若与原项目同时运行，还须使用不同后端端口并调整对应前端代理。

在仓库根目录启动：

```powershell
go run ./cmd/server -config configs/erp-test.local.yml
```

这是“新库初始化”，不是已有库升级包；现有升级CLI的本地库名、备份等限制保持不变。启动仍只读检查结构，不会自动补表或自动迁移。

## 文件与验证

`sources.sha256.json`记录本次源DDL/菜单定义、版本和SQL摘要。源文件变化后，先重新核对初始化快照，再运行以下只读检查；它不连接数据库：

```powershell
node scripts/check-erp-init.mjs
```

本次实际导入及登录结果见[验证记录](./验证记录.md)。本文件只包含MySQL数据库初始化；Redis、运行配置及前端需要单独准备。
